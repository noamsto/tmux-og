# Status Bar and Window Grid

How the multi-line status bar is laid out and how `tmux-reflow-windows` sizes the grid.

## Two Icon Variables

- `@window_icon_display` — unpadded, used in `automatic-rename-format` (window tab names) and top-right status
- `@window_icon_padded` — fixed-width padded to `MAX_ICONS * 3 + 2` cells, used in status-format ENTRY for `|` separator alignment. Set by both `tmux-update-icons` (every 1s) and `tmux-reflow-windows` (on layout events)

Icon display width is computed per-icon from Unicode codepoint: nerd font PUA (U+E000-F8FF, U+F0000+) = 1 cell, emoji/other = 2 cells, plus 1 space each. `wc -L` is unreliable for nerd font glyphs (reports 0 for PUA range) and emoji with variant selectors.

**Task-runner icons (#1136).** `just`/`make` run their recipe in their own process group, so `pane_current_command` names the runner for the whole recipe. `tmux-update-icons` swaps a runner pane's name (not a `@bridge_proc` mirror's) for the first descendant of the runner that is neither a shell nor another runner (`resolve_runner_child` in `lib-icons.sh`; `just → sh → nix` gives `nix`, an idle runner keeps its own name) before it feeds `win_procs` and `sess_active_proc`, so the window icon and `@active_pane_icon` agree. The loop holds a `@R<pane_id>.` placeholder to keep icon order, and **one** `ps -Ao pid,ppid,comm` runs after the loop, only when a runner pane exists (no extra fork otherwise; `tests/runner-child.bats`). `#{pane_pid}` sits before `@window_task` in the `list-panes` row (the task stays last). A resolved agent command (`just` running `claude`) now counts as an agent process for `@window_has_agent`. The picker's `icons.go` is unchanged.

## Status Bar Layout

- **Line 0** (status-format[0]): Global — session name, git branch, directory, claude status (left; session agent icon is `claudeSegment` over hook+screen files — `aggregateSession` unions `panes/` and `screen/`); active pane icon + command (right)
- **Lines 1-4** (status-format[1-4]): Window list, dynamically reflowed. Single-line mode unsets session overrides to fall back to global format. Multi-line mode sets per-session overrides with `├─`/`╰─` tree prefixes.

tmux treats session-level `status-format` as all-or-nothing: setting any index at session level overrides ALL indices. That's why reflow must copy `FMT0` from global when setting session-level formats.

tmux renders at most 5 status lines, so the window grid is capped at 4 rows — and reflow only unlocks the 4th above `TALL_CLIENT_ROWS` (40) of `client_height`, since a 5-line status bar is only affordable on a tall client. Row 3 is bounded by `@window_split3`, which stays 999 at the baseline 3-row cap so row 4 renders empty.

Per-row trailing `│` separators derive from the loop-native `next_window_index` (tmux 3.8's `W:` loop next/previous vars, #104): a separator renders only when `next_window_index` is non-empty (a next window exists in the loop) and, for rows bounded by `@window_split*`, that next window's index still falls within the row. Row-level `├─`/`╰─` prefix selection stays driven by `@window_split*` vs `session_windows` — that's row-structural data from `reflow_fit_columns`'s column-width math, not a per-iteration loop fact, so it's still stamped rather than derived in-loop.

## Folding the bar (`prefix + Z`)

`prefix + Z` folds the whole bar to one line and back (#970). The bind flips the per-session `@og_status_folded` in one `set -F` (so a second press reads the first press's result) and runs `tmux-status-fold` backgrounded. That script only forwards to `tmux-reflow-windows --force`; reflow owns what a folded or unfolded bar *is*, and the switch is instant (no stepping, no animation).

- **tmux spells a one-line bar `on`.** `set status 1` is rejected (`unknown value: 1`); `tmux-reflow-windows` translates 1 to `on`, and a test reading `show -v status` sees `on`.
- **Reflow still computes the whole grid while folded** (labels, split points, `@reflow_key`), then stamps `@reflow_lines` (what the grid wants) and applies `status = 1` plus a session-level `status-format[0]` of the folded line. Because the cache key does not include the fold, every toggle runs the reflow with `--force`. The single-line `set -u status-format` is skipped while folded: it would flash the global info line for a moment.
- **The folded line** is a format expression, no new `#()` job: the session name tinted by `@claude_session_fg`, then *every* window in its real index order inside a tmux window list (`#[list=on]`). The current window is `idx: label` (clipped to 40 cells, mauve bold, carries `#[list=focus]`) and stays in place; every other window is `idx icon` (the `@window_icon_display` icon carries the state colour). It hosts the update-icons job through `#{E:@og_icons_job}`: the job was split out of global `status-format[0]` into that option precisely so the folded line, the only line left, keeps `@window_icon_display`, `@claude_session_fg` and the agent state ticking. Anything else that moves into `status-format[0]` and must keep running while folded needs the same treatment.
- **Scrolling.** When the list overflows the client width, tmux scrolls it around the focus item and draws `‹` / `›` (`#[list=left-marker]` / `#[list=right-marker]`) where windows are cut off. The markers must be declared *after* the first `#[list=on]` or they print as literal text. The current item must also end its focus range with a following `#[list=on]`; without it the focus extends to the end of the list and the left marker overwrites the first cells of the current window.
- **Remote parity.** A mirror window (`@bridge_win` or `@bridge_placed`) has its index tinted `#{E:@window_host_color}` (peach when unstamped, as for a dedicated mirror) and the `@icon_remote` glyph beside it; as the current window it also shows `@bridge_host`. `@session_host_marker` renders after the list (after `#[nolist]`), still on the folded line and not beside the session name.
- **Right segment.** A short form of the full bar's right side: the host (`#{host_short}` dim; for a mirror current window its `@bridge_host` in the host colour) plus `#{@og_usage_short}` (`enrichment.md`; mirror sessions show the local usage). tmux trims the list, never the right segment, to make room, so the segment is gated in-format: it renders only when `#{w:}` of the list, session name, marker and right text (`#{w:}` ignores `#[..]` styles) fits `#{client_width}`. The gate is live, never stamped, so the right side is the first thing dropped as the width shrinks.
- **Last press wins.** There is no token or lock in the script any more. The flag is flipped atomically by the bind, and `tmux-reflow-windows --force` re-reads the live flag after acquiring its `reflow_lock` (the fast-path read happens before the lock, so only a forced pass pays the extra fork), so overlapping presses converge on the final flag. `tests/status-fold.bats` pins the instant switch (no intermediate `status` values) and renders the folded line in a real attached client for order, overflow, remote and right-segment behaviour.

## Grid Column Widths

Columns are sized independently, one width per column rather than one `colw` for the whole grid: alignment only requires a width to match *down* a column, never across, so charging every column the widest window's width overflowed the row (#271). `reflow_fit_columns` (in `lib-reflow.sh`) takes two per-window widths — a **floor** (issue id + agent badge + zoom marker, none of which the renderer can shrink) and a **want** (floor + branch/title) — gives each column its floor, then hands the remaining slack out in proportion to unmet demand. The PR badge forms a column of its own beside the label, sized the same way and for the same reason (#688): `pr_colw` was the widest badge in the *session* and rode `overhead`, so one `#1234` cost the row `per × 7` cells and padded every PR-less window to it.

`MAX_REST_WIDTH` caps what a want may *claim* while the row is tight, so one very long title cannot stretch the grid — but the cap does not survive a row with cells to spare. Once every capped want fits, `reflow_fit_columns` hands the leftover out toward the real labels in proportion to what the cap took, and a column already showing its whole label does not grow, since that would only add trailing padding. Before #688 it returned the capped wants verbatim: the 5-window session behind #686 rendered 206 of 245 cells with two titles ellipsised.

The renderer must never emit a label wider than its column. When even the floors overflow, `tmux-reflow-windows` drops the agent badge first (decoration) and clips the issue id only as a last resort — so `@window_label_id` stays the full identity for the pickers and the single-line global format, while `@window_label_id_disp` is the grid's column-clipped copy.

**Host badge on a placed tab (#985).** A mirror window placed into a local session (`@bridge_placed`) carries `<@icon_remote> <@bridge_host> ` in `@thm_peach` right after `index: `, before the agent badge, so it reads as a remote tab among local ones; no other window gets it, a dedicated mirror included. Reflow builds it per window (`win_host`, read through one extra `list-windows` field gated on `@bridge_placed`, so a `|` in a stray window-scoped `@bridge_host` cannot shift the row; `@icon_remote` rides the fast-path `display-message`, one read per pass) and charges its width wherever the agent badge is: the column floor, `total_long` and `total_short`. When a column cannot hold floor + id it drops the host badge *together with* the agent badge, before the id is clipped. The result is stamped as `@window_host_disp` in the same per-window exec as `@window_crew_disp`; the grid renders it before `${CREW}`, emitted only when some window has a badge (the `crew_colw` pattern). The single-line global `status-format[1]` (tmpl + `tmux.conf.reference.nix`, byte-identical) renders the same segment off `@bridge_placed`/`@bridge_host` directly; `host-badge-conf-assertions` pins it.

**Repo tag on a foreign worker window (#1165).** `status-format[1]` draws `<@crew_repo> ` in `@thm_peach` right after the host badge when the dispatcher-stamped `@crew_repo` is set, differs from `#{b:session_path}`, and the window is not a `@bridge_placed` mirror (which already shows its origin). Windows without `@crew_repo` render unchanged. The format lives once, as `crewRepoTag` in `generator/render/status.go` (spliced via `.CrewRepoTag`; mirrored byte-for-byte in `config/tmux.conf.reference.nix`); `TestCrewRepoTagEvaluates` runs it through a scratch tmux for unset/equal/different/mirror. `tmux-reflow-windows` neither draws it in the multi-line layouts nor counts its width in the single-row fit (`win_host_dw` has no sibling), so a row near the limit can clip rightmost tabs; deferred. `#{b:session_path}` is the session directory's basename, so a session opened on a worktree compares against the worktree directory name.

**Per-host colour (#1102).** The badge and the tab's index take a per-host colour instead of flat peach. `picker/hostcolor` is the single owner of the host-to-slot assignment, shared with the session picker's `hostColorFunc`; bash never copies the algorithm. Reflow makes ONE `tmux-picker-generate host-colors` fork per full pass, only when a placed window exists, and stamps `@window_host_color` = `#{@thm_<slot>}` per window (empty on non-placed windows, in the same per-window exec as `@window_host_disp`). The grid `ENTRY` and the global `status-format[1]` colour the index and badge through `#{E:@window_host_color}` (`E:` expands the stored `#{@thm_x}`), then re-assert the tab colour; when the call fails the stamp is empty and the badge falls back to peach. The palette order comes from `@remote_bridge_hosts` (read on the fast-path `display-message`, `|` squashed to a space). `@session_host_marker` is a session option, `⇄ h1 · h2` (hosts sorted, each in its colour), set by reflow and unset when no placed window remains; `tmux-statusline` renders it on line 0 after the status indicators (dir, claude and dispatcher segments), never beside the session name, so it reads as "this session contains mirrors from" and not "this session runs there"; the `prefix + Z` folded line carries it at its end, after the agent windows. The lead-in is a literal dim `⇄`, not `@icon_remote` (that icon is the per-tab "runs there" badge, which stays on window lines). **Top-right host:** the right block is `host  usage  paneSlot`: the active window's host, the local `host_short` dim for a local window, `@bridge_host` in its #1102 colour for a mirror window (placed or dedicated). It is rendered in the existing statusline `#()` tick, so a window switch shows on the next tick like the branch/dir segments, with no new fork. A dedicated mirror session keeps its host badge beside the session name and also shows the host top-right (twice, by design). The name-side badge is gated on `@session_host_marker` being empty, so a dedicated session that also holds placed mirrors from another host loses the name-side badge but keeps the top-right host. Hosts are restricted to `^[A-Za-z0-9][A-Za-z0-9._@-]*$` (the launcher's/daemon's accepted names; `@` is inert in tmux formats) because the marker is format-expanded (`#{E:}`); others get no colour or marker entry (the same regex gates `picker host-colors`). Host sorting is a pure-bash insertion sort (`LC_COLLATE=C`, no `sort` fork) and the marker unset rides the existing `tmux_cmds` batch, so the one `host-colors` call is the only added fork. The marker is set by direct argv, never the `source -` batch (its `#[`/`#{` would be re-parsed). **Staleness:** colours and marker recompute only on a full reflow pass (the `@reflow_key` cache skips them), so a changed `@remote_bridge_hosts` shows after the next structural event or a forced reflow. `tmux-statusline` takes `--thm-teal/pink/yellow/sky` for the dedicated-mirror badge and reads `@remote_bridge_hosts` live.

A row is given up only once clipping can no longer save it (#686). `total_long` charges each window its own PR segment, so a badge arriving (`" <glyph> #<n>"`, 6-7 cells, +2 with the draft marker prepended) can push a full row past `available` — and the grid it falls into costs a whole status line *and* caps every label at `MAX_REST_WIDTH`, so it shows *less* text than the row it replaced. Rung 1.5 therefore shaves the overshoot off the widest labels instead (`reflow_clip_rests`, water-filled: every rest above a common cap is cut to it, so a short label never pays) and keeps one row, falling through to the grid only when a clipped label would drop below `SINGLE_CLIP_FLOOR` (16 cells of branch/title). The clip lands on `@window_label_disp` alone, which is why the global `status-format[1]` renders that rather than the `@labels_mode` ternary over `@window_label_rest_long`/`_short` — those stay the full identity `picker/main.go`, `tmux-statusline` and the bridge's `windowlabels.go` read.

## Sizing for the narrowest client (#1038)

The layout is per session but every attached client renders it, and each reflow hook passes the *triggering* client's `client_width` — with a 200- and a 120-column client on one session the grid used to flip between the two widths. `tmux-reflow-windows` therefore takes the minimum `client_width` over the session's attached **non-control** clients (`list-clients -t <session>`, `|`-delimited, `client_control_mode` skipped) as `WIDTH`; control clients are the remote bridge's connection, report a width, and must never set the layout. With no client attached it keeps the passed width (the bridge daemon reflows its mirror session from outside any client). `session_attached` rides the fast-path `display-message`, so `list-clients` forks only when a client is attached, and the `win_count:WIDTH:HEIGHT` cache key carries the effective width — a cache hit still exits before the lock. The passed width never joins the minimum — it may be a control client's or another session's — and is used only when no real client is attached. `client-detached[10]` (debounced to coalesce with a resize burst; the departed client is already gone from `list-clients` when it fires) re-reflows so the layout widens when the narrow client leaves; a narrow client leaving via `switch-client` is not covered (the old session keeps its layout until its next event); it needs its own `set-hook -gu client-detached[10]` clear line, since the bare `-gu` clears only index 0. Height is still the session's most recent client.

## Bridge resize nudge

A remote-bridge mirror session carries `@bridge_nudge`: the path its daemon's
watcher stats each tick instead of forking a size query (`bridge-daemon.md`,
#433). A reflow pass touches it on the way through — after the empty-width
bail so a no-client pass still does not stamp anything (#235), but before the
cache check, so a cache hit nudges too. That is how `client-resized` and
`client-session-changed` (the two events already routed here) also nudge;
`window-resized` and `client-detached` carry their own gated hooks in the conf.
The bridge publishes the path as a session option rather than a
session-scoped hook because a session hook array replaces the session's view
of the global one (#647) — the shadowing that left a mirror's window bar stale
until an unrelated event (#820).


## Pane border labels

The status bar clips a window's label to its column; the full title lives on a pane border instead (#858). `tmux-apply-theme-colors` owns `pane-border-format` **and** both border styles (`pane-border-style` / `pane-active-border-style`), rebuilt on every theme switch. The format picks the first matching branch per pane:

1. **Float label** — `@pane_label` (yazi, prdash, …): `━━ <label> ━━`, mauve when active.
2. **aeye carousel split** — `@claude_img_src` (aeye's own pane option; survives a remux relaunch, whose start command is `tmux-carousel-restore`) or a start command matching `*/bin/aeye *` (tmux quotes it, and the glob needs the trailing argument): `━━ aeye ━━`, and the border styles drop the crew colour for it. A **mirrored** aeye is detected by `@bridge_img_src`, the daemon's presence marker for the remote pane's `@claude_img_src` (#866, `bridge-shipped-state.md` "Remote Agent Status") — its start command is the renderer and the remote viewer's `pane_current_command` is its shell, so neither other test can name it.
3. **Role pane** — `@bridge_crew_role`, else `@crew_role`, other than `lead`: `━━ <role> <glyph> <state> ━━`, never the title. State follows the same selector as the role (`@bridge_crew_state` beside a bridged role, else `@crew_state`); the glyph vocabulary matches the dispatcher's `state_glyph` (working ●, idle ○, blocked ⚠, done/pr_open ✓, failed/exited ✗).
4. **Anchor pane** — the top-left, non-floating pane (`pane_at_top && pane_at_left`; the lead in a dispatcher grid, and the zoomed pane while zoomed). It does not follow focus: `━━ [⇄ <host> · ]<codename> · <glyph> <state>[ (watchdog)][ · <detail>] · <title> ━━`, each segment only when non-empty and the word `lead` never printed. The title segment shows only while `@window_label_clipped` is set (the status bar already shows an unclipped label). Title = `@window_label_id` + `@window_label_rest_long` (reflow writes both for mirrors too, from the daemon-sanitized `@bridge_label_*`). The host segment (#1168) is `⇄ <@bridge_host>`, gated on `@bridge_win` (a dedicated mirror's session-scoped `@bridge_host` is visible from the session's local windows too), coloured by `@window_host_color` when reflow stamped one (placed mirrors; a dedicated mirror's stamp is empty, so it is uncoloured); it counts toward the anchor condition and is charged in the title-width budget (`HOST_W`). Role panes and floats never show it. The terminal title (`set-titles-string`) in a mirror window reads `<session> / ⇄ <host> · <@bridge_proc>`, same `@bridge_win` gate; local windows are unchanged (asserted by `titles-conf-assertions`). Codename = `@bridge_crew_name` in a mirror, else `@crew_name` only while `@window_has_agent` (the status bar's #671 gate). `@crew_detail`/`@crew_source` are local only — the bridge does not ship them. A state-only anchor (state, no codename) draws `━━ <glyph> <state> ━━` whenever the window has a title, clipped or not; with no title at all it falls to the plain branch, as does an anchor whose only content would be an unclipped title.
5. **Plain split** — the active pane of an unzoomed multi-pane window keeps the green `●`; the active pane of a sole or zoomed window has no label, so its border is one unbroken line in the active colour; every inactive pane is a plain `━━━━━`. A mirror window's codename no longer repeats on every non-role pane: it rides the anchor only.

**Tabs render `@window_label_*`, never `#{window_name}`** (#1157). Reflow's inputs for a local window are the enrichment options (`@issue_*`, `@pr_*`, `@branch`, `pane_current_path`, `@window_task`, `@window_ai_name`) and, for a typed rename, `@window_manual_name` + `automatic-rename` + `window_name`, all read through the `list-windows` FMT (`window_name` is `s/[|]/ /`-wrapped so a `|` cannot shift the trailing fields). When `@window_manual_name` is `1` and `automatic-rename` is off, the label is the typed name: `@window_label_id` empty, the name stored raw in `@window_label_rest_short`/`_long` (`#` unchanged, `|` squashed to a space), PR segment still appended. No tmux hook covers both cases cleanly (`window-renamed` fires before the `prefix + ,` bind sets `@window_manual_name`, and on every automatic rename; there is no cwd hook for a shell without OSC 133 prompts), so a reflow for either comes from `tmux-update-icons`' `@window_label_seen` memo (`enrichment.md`).

**`@window_label_clipped`** is a reflow-owned window option: `1` when the drawn status label (`@window_label_id_disp` + `@window_label_disp`, unpadded) differs from `@window_label_id` + `@window_label_rest_long` — a rung-1.5 clip, short mode or grid truncation — and unset otherwise. Written for mirrors too, only on change, riding the existing per-window argv exec and read back through the `list-windows` FMT. Titles are no longer cut at 50 at stamp time (`sanitize_title` caps at 256, the daemon title cap is 257, line 0 clips itself with `line0TitleRunes` 50, `line0MirrorRestRunes` 51, `line0BranchRunes` 120 in `picker/statusline/main.go`), so single-line rung 1.5 may show more of a long title than before. A window on a live server lacks the option until its next non-cached reflow (home-manager activation forces one on every session); a mirror gets the full title only once the remote host runs the new cap too.

If the anchor is itself an aeye or role pane, the window shows no title — it never moves to another pane. A float is never the anchor: the tiled top-left pane under it keeps the title.

**Clipping.** tmux draws a border label in `pane_width − 2` cells starting at x=2 (measured on the pinned tmux with an attached client). The title is clipped with `#{=/W/…:…}`, where `W = pane_width − 9 − (each prefix segment's #{w:} + 3)`: 7 cells go to `━━ `, ` ━━` and the `…` that tmux appends *beyond* W. W is floored at 1, because a 0 limit means "no clip" and a negative one keeps the tail. Widths use `#{w:}` (display cells), never `#{n:}` (bytes).

**Border colour.** fg = aeye → mauve/overlay_1; else `@bridge_crew_role_color` → `@crew_role_color` → `@bridge_crew_color` → `@crew_color` (while `@window_has_agent`) → mauve/overlay_1. Moving the styles out of `tmux.conf` also means `tmux-client-theme`'s recovery replay (catppuccin, then this script) no longer leaves catppuccin's border style in place.

**Dispatcher overrides.** A window- or pane-level `pane-border-format`/`-style` beats these globals. The dispatcher still sets them on local grid windows (`publish_grid_lead`, `decorate_pane`), so local dispatcher grids keep its border until it stops doing so and only stamps the options above. `tests/pane-border-format.bats` pins that precedence.

## Dispatcher segment on line 0 (#1083)

`picker/statusline` appends a server-wide segment right after the agent segment, before ` #[align=right]`: `iconDispatcher` + the dispatcher count, hidden at 0. It reads `#{@og_dispatchers}` — the last `volatileFields` entry (24 fields), so no extra tmux call — and renders outside the `claudeTrusted` gate since it reads a tmux option, not the status dir. Go owns the ranking: needs-human (`error` > `waiting` > `denied`) > working (`compacting`, else `processing`) > `standby` > idle (`idle`/`done`/`interrupted`/unknown), tinted with the matching `claudePalette` hue. Mirror windows never count (the producer skips `@bridge_win`); see `agent-state.md` for the producer and the standing-by window icon. The glyphs are named constants (`CLAUDE_ICON_STANDBY`, `iconDispatcher`) rather than `@icon_*` options, like the other agent-state glyphs.
