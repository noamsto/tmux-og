# tmux Gotchas

The measured evidence behind the one-line rules in `CLAUDE.md`.

## Session Targeting Gotcha

Numeric session names (e.g., "10") cause ambiguity with `tmux set -t '10'` when piped through `tmux source -`. The Go TUI targets sessions by name (`tmux switch-client -t <name>`; zoxide suggestions use `=name` exact-match when creating a new session). Direct `tmux set` calls (as in update-icons) work fine with session names — except a numeric one: `set-option -t` takes a target-pane, so a bare `0` also resolves as pane index 0 of the current window, and from a hook or `run-shell` context the write lands on whichever session is current (measured, #693). Target by session id (`-t '$N'`) when the name may be numeric.

**`show-options` does not accept the `=` exact-match prefix.** `has-session`, `switch-client` and `kill-session` all take `-t "=name"`; `show-options -t "=name"` answers `no such session`, and `-q` turns that into an empty string indistinguishable from an unset option — so a script can stamp an option with `set-option -t "$name"` and never read it back. That silently disabled `og-remote-open`'s mirror dedup, forking a `-remote` session on every re-open (#474). Read session user-options with a bare `-t "$name"` (an exact match still beats a prefix match), or via `display-message -p` / `list-sessions -F`.

**`display-message -p -t '$N' …` against a gone session id is not an existence probe.** With a client-less caller it exits 0 and prints EMPTY fields rather than erroring "can't find session" (measured, next-3.9) — a target string that merely parses (`$N`) is accepted even when nothing answers behind it. Comparing the echoed id (or pid) against what was asked for is the only way to tell "gone" from "answered" (`ownsLocalSession`, `picker/remotebridge/daemon/ownership.go`, #817). Separately, a **bare session name** still resolves exact-then-unique-prefix for any command that takes a session target — use `=name` where a command accepts it (`attach-session`, `has-session`, `switch-client`, `kill-session`), or target by `$id`; `set-option`/`show-options` reject `=name` outright (above).


## Formats, scratch servers, background pollers

- **A pane's default shell is a *login* shell, and on darwin that rewrites `PATH`.** `bash` as `-bash` sources `/etc/profile`, whose `path_helper` replaces `PATH` with the host's own list — every store path drops out, so a script that a key binding, a monitor hook or `run-shell` finds by bare name is `command not found` (rc=127) when a pane is asked to run it (#1004). Key bindings and hooks are immune (they run in the server's environment, not the pane's); only what a *pane* executes is affected, and only where the login profile rewrites `PATH` — which is why `picker-session-kill-tests` passed on x86_64-linux and aarch64-darwin CI and failed on a local aarch64-darwin run. Naming the tool by absolute store path (and prefixing the wrapper's bin dir onto the pane's `PATH` when the shebang needs its `bash`) makes the test host-independent; `checks.<system>.picker-session-kill-tests` passes `PICKER_BIN_DIR` for exactly that.
- **tmux `-F` formats are `|`-delimited, never tab-delimited.** tmux rewrites non-printable bytes in command output to `_` unless the *querying client* is UTF-8 (the client decides, not the server), so a tab-delimited format collapses to a single field and every consumer parses garbage. That silently deleted every agent state file once per 5s and made `nix flake check` flaky on both platforms (#373). `checks.<system>.tmux-format-delimiter-assertions` enforces this over `scripts/`, `config/`, and `modules/` — it rejects both a raw control byte and a `$'…\t…'` escape, and scans whole files so a format hidden behind `-F "$FMT"` is caught at its definition. `picker/**` is gated the same way by `go test ./tmuxformat/...` inside `picker-go-tests`. `\n` is rejected too — tmux mangles a newline exactly like a tab, which had collapsed reflow's own 3-line `-p` read. Multi-byte UTF-8 is allowed (reflow's status-format strings carry `├─` glyphs, which are printable). The exposure is narrower than "the client's locale": `CLIENT_UTF8` is set whenever `TMUX` is in the client's environment (`tmux.c:509`, "tmux is a UTF-8 terminal, so if TMUX is set, assume UTF-8") and by `-u`, so every hook, `#()` job and anything run from inside a pane is immune — only *detached* callers with a non-UTF-8 locale (systemd units, the nix check sandbox, `ssh host tmux …`) can be bitten, and `tmux -u` fixes those. The `|` rule stays a defensive default either way, since a format outlives the call sites that read it.
- **Every hand-rolled tmux repro opens on its own socket in its own `TMUX_TMPDIR`.** Inside a pane `$TMUX` is set, so a bare `tmux new-session` builds on the **live** server — a detached one-window shell nobody attaches and nothing reaps, which resurfaces days later as a mystery session (`t`, `p` and `probe` all leaked this way; the tell is an empty `#{session_last_attached}`). A bare `tmux kill-server` is the same mistake with the user's whole server as the blast radius. Reading the live server (`list-sessions`, `show-options`, `capture-pane`) is fine and usually the point — it is *creating* on it that leaks. So: `TMUX_TMPDIR=/tmp/og-$$ tmux -L probe new-session -d …`, then `kill-server` when the repro is done; the private dir confines a forgotten server to a path you can find, and the socket path is capped at ~108 bytes, so keep the dir short. tmux leaves the socket *file* behind on exit either way, unlinking a stale one only when a new server claims that name, so a shared `TMUX_TMPDIR` grows one dead entry per run. Every test here already works this way: the bats suites set a per-run `TMUX_TMPDIR`, and the Go tests that start a live tmux use `os.MkdirTemp("", "lz")` and pass it through the command env. **A private `TMUX_TMPDIR` does NOT isolate `CLAUDE_STATUS_DIR`** — it defaults to `/tmp/claude-status-<uid>` (#850), shared by every tmux server of your uid, not per-`TMUX_TMPDIR`. A scratch server run as your own user therefore shares the real server's agent state, and both its config-load `run-shell` (unconditional, on every boot — not client-gated) and its per-tick status-format call (client-gated) prune and reap from that shared directory exactly as they always do — export `CLAUDE_STATUS_DIR` to a scratch dir too, the way the bats suites already do. `claude_prune_stale_state`'s per-`server=`-owner PID-liveness check (#676) protects a real, still-live server's `panes/<id>` files from a scratch server's boot, but a scratch server with no client (and so no real agent panes of its own) still has nothing of its own to protect the real server's other state files with, so isolating `CLAUDE_STATUS_DIR` remains the actual requirement here, not something this guard makes optional. The tick is not the only destructive writer: `pane-exited`/`pane-died` fire `tmux-reap-pane` with no client and no status line at all, so even an unattached scratch server unlinks under the shared dir (ownership-guarded only when the colliding `panes/<id>` carries a `session=` this server lacks). (The `@og-sweep-tick` monitor hook, #603, is exempt: it only arms `agent-detect`, which is non-destructive — see the `tmux-update-icons` row above.)
- **A background side effect must not be driven from `status-format`.** `status_line_size()` returns 0 for any control-mode client, so `status_redraw()` returns before expanding `status-format[0]` and none of its `#()` jobs ever runs — which froze `tmux-pr-enrich`, `tmux-issue-stamp --backfill`, `tmux-agent-usage`, and `tmux-update-icons`' full-server sweep on a host whose only clients are remote-bridge transports (#603). The test is artifact privacy, not whether a human is looking: the shorter rule "a client that renders no status line needs no text" is false on a bridge host, because a bridge is a consumer that is not a status client — the same reason `@bridge_proc`, #589 and #590 exist. Those four now run from tmux 3.8 `-B` monitor hooks (`@og-pr-tick`, `@og-backfill-tick`, `@og-usage-tick`, `@og-sweep-tick`, every 5s) instead, which fire off the server's own clock with zero clients attached; `@og-res-tick` (`tmux-session-resources`, #693) is the fifth, born on the mechanism rather than frozen into it — and the one whose own pass is gated on a control-mode client being attached or `@og-usage-tick` being armed (#969), since otherwise nothing reads what it would stamp: the session rows stay bridged-only, the per-pane `@og_pane_agent` stamp also feeds the local usage segment and poller (up to ~5s stamp latency). Three traps in that mechanism:
  - A monitor hook's target field is **empty** for a session monitor (`@name::<format>`), never the word `session`. `monitor_parse` requires it, and upstream commit `557967c3` turned the permissive fallthrough into a hard failure, so `:session:` works on the current pin and dies on the next `flake.lock` bump.
  - A version guard around `-B` must pass its body as a **string**, not a brace block, because tmux parses every branch at source time and rejects the unknown flag even when the condition is false — `config/tmux.conf.nix:691` already records this for `floatNewPaneGuard`.
  - Each `-B` hook needs an unconditional `set-hook -g -u -B` clear paired with a `set -gu`, above the conditional setters. Setting a monitor replaces a same-named one, but **disabling** it does not: without the clear, a rebuild with the feature off leaves the old monitor firing at a garbage-collected store path for the life of the server. The `-u -B` form removes the monitor but leaves the option string, which is what the paired `set -gu` cleans up.

## Multi-client environment (#1037)

- **Per-machine env is pinned from local clients, never copied on every attach.** `update-environment` copies each listed var from the attaching client into the session and marks it removed when that client lacks it, so a laptop ssh-attaching to a desktop's server overwrote the desktop's `DISPLAY`/`KITTY_LISTEN_ON` (panes lost kitty remote control or opened on the wrong display). The conf spells out tmux's default list minus `DISPLAY WAYLAND_DISPLAY WINDOWID XAUTHORITY` (the `KITTY_LISTEN_ON`/`AEYE_HOST` additions are gone too), and `client-attached[30]` writes those six vars, plus `KITTY_LISTEN_ON` and `AEYE_HOST`, only when the attaching client has no `SSH_CONNECTION` and the var is non-empty. A local client lacking a var leaves the previous value (it used to remove it). The default list is spelled out because there is no way to subtract from it; re-check it against `tmux show-options -gv update-environment` after a tmux bump.
- **The hook omits `-t` and writes both scopes.** Inside a hook, `#{I/e:VAR}` reads the attaching client, but `set-environment -t "#{hook_session}"` is a silent no-op (measured). Bare `set-environment -F` targets the hook's session; `set-environment -gF` also writes the global env, which sessions created later inherit.
- **`SSH_AUTH_SOCK` and the other `SSH_*` vars stay in `update-environment`: last attach wins.** A remote client's panes need its own forwarded agent. The trade-off: when a laptop attaches after the desktop, new desktop panes in that session get the laptop's agent socket until the desktop reattaches.
- **Re-adding a pinned var through `extraConfig` (`set -ga update-environment DISPLAY`) reintroduces the leak.** `update-environment-conf-assertions` checks only the generated conf.
- **Keybinds read the invoking client, not the session.** The `C-hjkl` binds pass `client=#{?client_name,#{q:client_name},}` (always one token; a bare `#{q:}` of an empty value is zero words) as `tmux-smart-nav`'s 8th arg, and the script resolves `#{?#{I/e:SSH_CONNECTION},,#{I/e:KITTY_LISTEN_ON}}` for that client at a window edge, so an ssh client's keypress never drives the desktop's kitty. Resolve in the script, not the bind: `#{q:#{...}}` does NOT shell-quote (the nested expansion runs first and `q:` then sees a plain string; `conf-shell-quoting.bats` rejects it). The arg is authoritative when present, even as `client=`; absent, the script falls back to `$KITTY_LISTEN_ON`.
- **Test it with real pty clients.** `tests/multi-client-env.bats` attaches via `script -qfc`; keep the client's stdin open (a fifo held by `sleep`) or `script` types ^D into the pane and the session dies.
