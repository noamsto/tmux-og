# Script Roles

Every packaged script: how it is invoked and what it owns. Disclosed from `CLAUDE.md`, which keeps the one-line index.

| Script | Invocation | Purpose |
|--------|-----------|---------|
| `tmux-update-icons` | `#()` every 1s (status-interval); its full-server sweep also runs from the `@og-sweep-tick` monitor hook (every 5s, dispatched via `OG_TICK_SWEEP=1` in the hook's environment, never argv — a session literally named `--sweep` must not be misrouted) | Sets the per-window `@window_icon_display` (unpadded) and `@window_icon_padded` (fixed-width), plus the **session**-scoped `@active_pane_icon` (`set -q -t '$s'`, not `-w` — so a reader using `show-options -w` never sees it). Reads claude status files. Builds a pane's icon from `@bridge_proc` when it has one (a remote-bridge mirror pane, whose own command is the renderer). The sweep reaps `panes`/`screen`/`interrupt`/`tasks`/`issues`/`watchers` state as a ~60s backstop (per-tick caller only, `CLAUDE_NOW % 60`) covering the death paths no pane hook fires on (`kill-pane`/`kill-window`/`kill-session`/`respawn-pane -k`/server crash — measured), skipping every id whose `panes`/`screen`/`watchers` file names another live tmux server in `server=` (#711; id-scoped, so it under-reaps rather than over-deletes); the common process-exit path is hook-driven. It also prunes stale state on server start — server-wide, from the unconditional config-load `run-shell` (which is **not** client-gated and runs on every boot, detached or not) and the per-tick, client-gated status-format call (which passes `#{pid}` as `$6`; the config-load site passes only `$1` and takes the live-query fallback), never from the monitor hook. `CLAUDE_STATUS_DIR` is a bare `/tmp` path shared by every tmux server on the machine, so mtime alone cannot tell a dead server's leftovers from a live different server's fresh state (#676): `claude_prune_stale_state` is handed this server's `#{pid}` and protects any `panes/<id>` whose `server=` stamp (written by `claude-status-update` and the bridge daemon's `agentShipper`) names a different, still-live tmux process, across every dir it sweeps. `screen/` and `watchers/` carry the same `server=` stamp (written by `agent-detect` and the bridge shipper), so a screen-only agent pane is protected too; only legacy files with no `server=` still fall to mtime alone. A caller that cannot resolve this server's `#{pid}` skips the destructive sweep entirely instead of falling back to mtime alone — the fallback is exactly the #676 hazard, so the skip is logged as `prune_skipped` via `log_event` and retried next tick (#712). The hook arms `agent-detect` only — non-destructive, so it's the one side effect that stays on the client-independent timer — and bypasses the per-tick `CLAUDE_NOW % 5` throttle, since the hook itself is the cadence (#603). The per-tick, client-gated caller's same batched read also re-derives window enrichment when a window's cwd has moved out of the repository its stamps describe, handing the window's first non-floating pane to `tmux-reconcile-window` (#596) — this stays off the monitor-hook path, which returns after arming and never reaches the per-window loop. Also tracks per-window agent occupancy (`@window_has_agent`), the durable `@window_manual_name` marker and the `@window_naming_dirty` mark in the same batched read; on a genuine occupancy transition, or when the sweep left that mark, it either stamps `@window_has_agent 1` or, with no live agent, calls `claude_clear_window_naming` (#671/#692) — the backstop for a window an OSC-133 prompt event never reaches (no client, or a shell with no OSC 133 support). The `@og-sweep-tick` path (`arm_agent_detect force`) computes the same occupancy from its own `list-panes -a` rows and, when a window has no live agent but still carries naming state — including one whose `@window_has_agent` was never stamped, the bridge-only host itself (#692) — clears `@window_has_agent`/`@window_ai_name`/`@window_task` and forces a reflow: option writes only, no shared-dir deletion, marking `@window_naming_dirty` so the client-gated per-tick pass discharges the file deletion. The per-tick task/name file reads are gated on live occupancy, so a lingering file cannot re-stamp an option the sweep cleared. The pre-existing automatic-rename reassert this same per-window loop already forces now also respects `@window_manual_name`, leaving a genuinely user-renamed window's `automatic-rename off` alone instead of reverting it within ~1s. The main `list-panes -a` read (#725) filters `-f NOT_MODAL` and reads `EFF_ACTIVE` in place of `pane_active` for the 11th field, so a popup-float open on the window neither joins its icon list nor steals `@window_task`/`@window_ai_name`/`@active_pane_icon` from the agent pane underneath — see `floats.md`'s chrome rule; `tests/update-icons-modal.bats` pins it on the pinned wrapper (nixpkgs' tmux has no `pane_modal_flag`). |
| `tmux-reap-pane` | `pane-exited`/`pane-died` window hooks with `#{q:hook_pane}` | Deletes exactly that pane's `panes`/`screen`/`interrupt`/`tasks`/`issues`/`watchers` files via `claude_reap_pane`; never iterates a directory (`CLAUDE_STATUS_DIR` is shared by every tmux server and pane ids are per-server `%N` counters). Ownership guard: when `panes/<id>` exists with a non-empty `session=` field, skip when this server has no such session; a pane with no `panes/` file (screen/tasks/watchers-only) or an empty `session=` passes that check. Then a second guard, `claude_pane_owned_elsewhere` (#711): it skips when any of `panes/`/`screen/`/`watchers/` for that id carries a `server=<tmux pid>` naming a different, still-live tmux server (a screen-only pane's only protection). Residuals: a legacy file with no `server=` still deletes unguarded, and same-named sessions on two servers then collide; `rename-session` fails closed to the backstop. `names/`/`live/` excluded (monotonic ids, prune owns them). |
| `tmux-shell-prompt` | `pane-shell-prompt` hook (OSC 133;A) with `#{q:hook_pane} #{qs:pane_current_command} #{qs:session_name} #{q:window_id} #{q:@window_has_agent}` | Clears an exited agent's state from the shell's own prompt mark (#646): `claude_clear_agent_state` removes `panes`/`screen`/`interrupt` for that pane and empties `@claude_status`/`@agent_screen` (the bridge shipper's source). The discriminator is the same `@AGENT_COMMANDS@` manifest the sweep arms from: a nested prompt inside a still-running agent keeps the agent as `pane_current_command` and is skipped; `session_name` (never `session_id`, whose `$N` re-expands in `run-shell`) carries the ownership guard matching the file's `session=`. The two trailing args (`window_id`, the window's current `@window_has_agent`) exist for the #671 window-wide naming reset trigger — no extra fork needed to fetch the value. That reset takes only the *option* half here (`claude_clear_window_display`) plus `@window_naming_dirty 1`: this hook is server-side, so it fires with or without an attached client, and the shared-dir `rm`s stay on the client-gated per-tick pass (#692), which clears the mark last. |
| `tmux-reflow-windows` | tmux hooks (window add/remove/resize) | Computes multi-line window layout split points, sets `status-format[1-4]` and `status` line count (2-5), stamps `@window_per` (grid columns/row). Sizes each grid column to the windows stacked in it rather than charging one width to all (#271). Caches by window-count:width:height key to skip no-ops. |
| `tmux-window-nav` | `M-J`/`M-K` (Alt+Shift, no prefix) | Moves the window selection down/up a row in the reflowed grid: jumps `±@window_per` in window-index order, clamps down to the last window when the column below is missing, no-ops at the top/bottom edge or in single-line mode. (`M-H`/`M-L` cover horizontal.) |
| `claude-status` | `#()` in status-format[0] | Reads `/tmp/claude-status/panes/*` files, aggregates per-pane/window/session with priority (error > waiting > denied > compacting > interrupted > processing > done > idle). Handles staleness fade and interrupt reclassification (both in `read_pane_state`). |
| `claude-status-update` | Claude Code hooks (external) | Writes state files to `/tmp/claude-status/panes/<pane_id>`; `issue add|done|clear <ID>` maintains self-reported issue ids in `/tmp/claude-status/issues/<pane_id>`; `task set <text>|clear` maintains a freeform "what Claude is doing" phrase in `/tmp/claude-status/tasks/<pane_id>` (auto-captured from the latest prompt by the CC plugin's `UserPromptSubmit` hook); `name set <title>|clear` maintains a window title in `/tmp/claude-status/names/<pane_id>` (the `UserPromptSubmit` hook seeds it from the first prompt on an unnamed fallback window, then nudges the pane's Claude once to upgrade the seed — the seed flips the gate so the nudge fires only once). Separate files — state hooks fire around the very call that stamps, sharing a file would lose updates. Called by the CC plugin's hooks / skill. Every write also mirrors into the pane options `@claude_status` (`<state> <epoch> <unseen>`), `@claude_task`, `@claude_issues` via `bridge_stamp` (folded into the refresh call it already made) — the only way this state reaches a remote-bridge host. `task`/`name` additionally stamp the *window* options `@window_task`/`@window_ai_name` via `window_stamp`, from the window's active pane only and skipped when unchanged: `tmux-update-icons` is their sole other writer and it is a 1s `#()` poller, so on a host whose only clients are bridges it has never run and every mirror window rendered the repo basename (#589). It forces a reflow, since the label is what reflow builds from them. `window_stamp`'s "active pane only" read is `EFF_ACTIVE` (#725): without it a popup-float open on the window is the window's active pane and the reporting agent's own pane reads as inactive, so the stamp would silently skip — see `floats.md`'s chrome rule. |
| `tmux-session-picker` | `prefix + s` | Launches the Go bubbletea picker (`tmux-picker-generate --tui`) in a popup: sessions sorted by activity (`sortSessionsForDisplay`, plain), and — only once a filter query is typed — the currently attached session sunk below any same-display-name peer on another host (`sinkCurrentMatchBelowPeer`: fuzzy score alone always favors the bare name over its host-prefixed mirror, so the current session wins a rank nobody wants; an empty query stays the plain activity order a user reads positions off, so the sink is the filtered list's alone. Current-ness is sourced via `--current #{qs:session_name}` on the bind, carried to the popup as `OG_PICKER_CURRENT_SESSION`, #551) (mirrors tagged with their `@bridge_host` in the Host column, which costs no width when there are none; `sessionDisplayName` trims the `${host}-` prefix `og-remote-open` baked into the name, for display only — the target and search text keep it (a mirror whose name lacks the prefix gets `@bridge_host` appended to its search text, so typing a host narrows mirrors and Remote rows alike), and the session is never renamed because window mode and everything outside the picker read the bare name), then the Remote section (a row per `@remote_bridge_hosts` host, its unbridged sessions as `├─`/`╰─` children). The Remote section paints from `$XDG_CACHE_HOME/tmux-og/remote/<host>.json` on first frame, so its sessions are searchable before any ssh probe answers, and the probe's result replaces those rows in place — `restoreCursor` holds the selection, since cached and live rows share targets (#631). Only an answered probe writes the cache (OK, or no-server as an empty list); the file is trusted only in an owner-only dir. Rows older than `remoteCacheStaleAfter` (5m) are dimmed with `(cached <age>)`. An **unreachable** host keeps its cached rows, always marked stale, while needs-auth, host-key-changed and tailscale-check hosts get none, so a cached row can never make Enter act on a host the probe just called inert. Then top-30 zoxide dir suggestions (Enter on a suggestion creates a session there and switches). Remote rows are exempt from the claude/scratch toggles — neither may take the section away. `hostColorFunc` hashes each host to one `@thm_*` tint (peach/teal/pink/yellow/sky — never mauve, red or blue, which local sessions, errors and the path icon own) and paints its Host cell, its mirror sessions' name, and its Remote-section row and children the same colour, so a mirror up top is visibly the same host as its block below. `^o` on a Remote row spawns a floating pane running `og-remote-picker <host>` — the remote's own picker — and quits the popup; the hint renders only on a row `remotePickHost` resolves, which in `prefix + w`/`prefix + W` is a mirror row via its `@bridge_host` (#498). Working from *inside* a mirror window is no longer refused: spec D7's gate existed because a float there broke layout reconcile, which #535 fixed. A host blocked on a Tailscale ACL "check" (`tailscale set --ssh` with an `"action": "check"` rule) renders `(tailscale check — run: ssh <host>)` and Enter refuses to act — not ssh auth, so `og-remote-auth`'s `ssh-copy-id`/`ControlMaster` remedy can't clear it and re-arms on the ACL's `checkPeriod` regardless; the fix is running `ssh <host>` yourself. `^o` still advertises "browse" and dials `og-remote-picker` on this row too, same as on a host-key-changed row — it will hang exactly as the probe did, a pre-existing gap this state doesn't close (#486). `^t` marks a Remote session row for multi-open, surviving the query and the cached→live swap alike; Enter with any marked opens all of them — the first via the usual foreground `og-remote-open`, the rest launched detached so N marks cost one serialized ssh dial instead of N — and switches to the first in list order (see `docs/agents/picker.md`, #730). Tab cycles a host scope — local → each configured host → all hosts → local — that filters the list to one host's (or every host's) sessions, reusing the Remote section's rows verbatim and appending rows for sessions already mirrored locally, whose Enter switches to the mirror instead of dialing out again; a search-row badge and `⇥:scope` footer hint show the active scope, and marks still resolve across every scope (see `docs/agents/picker.md`, #733). |
| `tmux-window-picker` | `prefix + w` | Same TUI in window mode (`--tui --windows`), grouped by session (default) or, via `ctrl+g`, by claude priority state — same order as `claude_priority_state` (error > waiting > denied > compacting > processing > done > idle), stateless windows in one trailing group, session name folded into the identity column. Resets to session grouping on every popup launch. Window rows show the enrich identity (`@window_label_id`/`@window_label_rest_long`) and a PR badge (`@window_pr_plain`, tinted by `@pr_check_state`/`@pr_mergeable`; its `#<n>` half takes `@pr_review`'s tint and a `@pr_auto_merge` underline instead); aligned columns, searchable by issue id / PR number. `^x` on a mirror window row sends the ctl `kill-window` verb rather than a local `kill-window` — the daemon reconciles only toward the remote, so a local kill strands a registry entry whose `localWin` is gone (#393); the footer hint reads `kill remote` on such a row, since `^x` is unconfirmed. |
| `tmux-window-wall` | `prefix + W` | Same TUI in wall mode (`--tui --windows --wall`): a tiled grid of live window previews, one batched `capture-pane` per tick. Fixed full-screen popup geometry — ignores `@picker_layout`. A focused tile (`tab`) expands to fill the wall body instead of keeping its grid-cell size; `esc` returns to the grid at the same page/selection. |
| `tmux-scratchpad` | `prefix + S` (outer mode: creates/reopens the per-session scratch session and opens the popup-float); its own `--attach <session>` argv is the popup-float's command (inner mode) | Toggles a per-session scratch tmux session in a `display-popup` compat modal float. Inner mode attaches with `env -u TMUX tmux -S "${TMUX%%,*}" new-session -A -s "$SCRATCH"` (#725): the popup is now a real pane on the same server, so tmux's nested-client check sees the same server twice and refuses a bare `new-session -A` (`sessions should be nested with care`) unless `TMUX` is unset first; the socket path taken from `$TMUX`'s own first field still reaches that same server, so inner mode's own `tmux set -t "$SCRATCH"` calls (~l.17-18, run inside the float with `$TMUX` still set, just before the `exec env -u TMUX tmux -S …`) address the session the nested client then attaches to. |
| `tmux-branch-display` | `#()` in status-format[0] | Shows git branch name from `@branch` or fallback to `git branch --show-current`. |
| `tmux-dir-display` | `#()` in status-format[0] | Shows pane path relative to git root (e.g., `./src`). |
| `tmux-float-refit` | `window-resized` hook | Reasserts each floating pane's `@float_geom` (the creation percentages) against the window's new size — tmux resolves `new-pane`'s `-x/-y/-X/-Y` into absolute cells once, with no memory of the percentage (#371). Upstream (tmux/tmux#5582, `f8fc53b6`, #651) now clamps a float fully inside the window on every resize, but only by shrinking/repositioning the existing absolute cell — it never re-derives "50%", so a float still renders at its old absolute size on a larger client. That's the half still ours. Skips floats with no stamp (a mouse Ctrl-drag float is the user's geometry, not ours) — upstream's clamp has no notion of `@float_geom` either, so it keeps those on screen for free. |
| `tmux-apply-theme-colors` | `run-shell` at config load | Interpolates `@thm_*` color variables into `pane-border-format` (needed because nested `#{@thm_*}` inside `#[]` don't expand at render time). Every `#[...]` block carries at most one style attribute (`bg` or `fg`), never a comma-joined pair — `pane-border-format`'s `#{?...}` ternary comma-splitter tracks nesting depth for `#{...}` but not `#[...]`, so a joined `#[bg=X,fg=Y]` is silently misparsed as an extra branch boundary and renders empty (#648). The same format carries the bridged dispatcher decorations — `@bridge_crew_role`/`@bridge_crew_state`, else the window's `@bridge_crew_name` — after the `@pane_label` branch and before the multi-pane `●` default. |
| `tmux-worktree-match` | worktrunk `post-switch` hook (navigation) | Resolves which window shows a worktree. One `list-panes -a`, filtered `-f NOT_MODAL` and reading `EFF_ACTIVE` for the active-pane field (#725) — so a `wt switch` run inside a popup-float (the scratchpad, say) contributes no row for the float itself, and "active" still names the pane underneath; ranks candidates by the `@worktree` tag **corroborated by a pane's cwd** (tag+active pane > tag+background pane > untagged window whose active pane sits there), so a tag that outlived the `cd` that earned it can't win (#199). Unsets a tag it proves false. Prints `<session>\t<window>\t<window_id>`, empty on no match. |
| `tmux-issue-stamp` | worktrunk `post-switch` hook (one-shot, backgrounded); its `--backfill` retry sweep runs from the `@og-backfill-tick` monitor hook (every 5s) | Detects the Linear/GitHub issue for the new window's branch via provider priority; writes `@issue_provider`/`@issue_id`/`@issue_title`/`@issue_url`, then kicks an immediate PR fetch. `--backfill` rescans every window for a partial stamp (id set, title or url missing) and retries it, so a window stuck that way is self-healing instead of stranded (#600). |
| `tmux-issue-stamp-linear` / `-github` | called by the dispatcher | Provider impls: branch regex (+ `linear`/`gh` CLI) → `id\ntitle\nurl`. First provider with a non-empty id wins. |
| `tmux-pr-enrich` | `@og-pr-tick` monitor hook (every 5s, `--tick`); `prefix + i` `r` (`--force`) | Background PR poller. Every gh call runs inside a checkout of the branch's repo (`--dir` / window `@worktree`/`@git_root`) — the poller's own cwd is the tmux server's, not a repo. Full pass groups windows by repo: fast PR-identity batches run every `prRefreshSeconds`, while check-rollup batches run every `prCheckRefreshSeconds`; per-branch fallback only handles heads with no open PR (cached at `/tmp/og-pr/`, 60s TTL, 1h for merged/closed, lock-guarded via the portable `acquire_lock`). Writes `@pr_number`/`@pr_title`/`@pr_state`/`@pr_check_state`/`@pr_url`/`@pr_draft`/`@pr_review`/`@pr_auto_merge`/`@pr_check_progress`. The gate stamps (`.last-tick`, `.last-check-tick`, `.last-pending-tick`, and `tmux-issue-stamp`'s `.last-backfill-tick`) and the pending markers carry a per-tmux-server suffix (`ENRICH_SRV`, from `$TMUX`, #705): `/tmp/og-pr` is shared by every tmux server on the machine but a pass enriches only its own server's windows, so an unsuffixed stamp let a scratch server's tick consume the gate and starve the real one — and its marker cleanup deleted the real server's markers. The branch caches stay shared (keyed by repo+branch), so two servers over one repo each pay their own check-rollup refresh. Scripts must not use `compgen` (absent from nixpkgs' non-interactive `bash`). A repo whose last applied rollup was pending keeps a `<sha1>.checks-pending` marker (content: the epoch it was first seen pending; mtime: its last checks refresh start) and re-polls checks about every 30s through a `--tick-run-pending` checks-only pass that skips the identity batch (cap and gaps under "PR + Issue Enrichment" in `enrichment.md`). Single-target mode exits immediately on a `@bridge_win` window — a mirror's branch belongs to the launcher's repo, not the remote content — so a bridged `[r]` is routed to the remote's own copy by the `enrich-refresh` ctl verb instead (#598). |
| `tmux-agent-usage` | `@og-usage-tick` monitor hook (every 5s, `--tick`) | Background usage-limit poller. A pass runs only while an agent pane exists (pane-command scan against the agentdetect manifest commands) and refreshes `/tmp/og-agent-usage/<agent>.json` per authed CLI, lock-guarded via `acquire_lock`. Rendered top-right by `tmux-statusline` (Go) — same live gate, so the segment vanishes when the last agent exits. |
| `tmux-agent-usage-claude` / `-codex` / `-cursor` | called by the dispatcher | Provider impls: curl the vendor usage endpoint with the CLI's own stored token (`~/.claude/.credentials.json`, `~/.codex/auth.json`, `~/.config/cursor/auth.json` — no extra API keys) → normalized `{windows:[{label,pct,reset_at}], monthly:{label,pct,reset_at}}`. Failed fetches keep the previous cache. Cursor chains four DashboardService calls (GetMe → GetHardLimit → GetCurrentPeriodUsage → GetAggregatedUsageEvents) to compute monthly spend-limit utilization. |
| `tmux-claude-images` | `prefix + I` | Toggle the image carousel for the invoking Claude session. In tmux: split pane keyed by `$TMUX_PANE` (bound to `prefix + I`). Outside tmux in kitty (remote control on): `kitty @ launch` window keyed by `$CLAUDE_CODE_SESSION_ID`, tagged `user_var claude_img_src`. Renderer + manifest shared across modes. |
| `og-remote-detach` | `prefix + d` in a mirror window / CLI | Detaches the bridge for a session: reads `@bridge_sock`, SIGTERMs the daemon and lets its teardown drop the mirror session (killing it directly only as the fallback for a daemon that can no longer run one). Non-destructive — the remote loses a control-mode client, nothing else. The shell twin of the picker's `stopBridgeDaemon`. |
| `og-remote-open` | `prefix + s` remote section / CLI | Opens a remote tmux session as native local windows via the control-mode bridge (`og-remote-bridge-daemon`). Outbound SSH only. When no session resolves (the remote has no server), starts the remote's own `tmux-startup.service` and re-probes — unit state is not server state, so the second `list-sessions` is the authority, never `systemctl is-active` (#287). `OG_REMOTE_NEW_DIR=<dir>` creates the named session on the remote in that dir first (sized `-x/-y` from the invoking client's content area, the same measurement the local mirror session gets — a session born at `default-size` 80x24 is what anything the shell autostarts sees until the daemon's converge lands) (cold-starting the server if needed, then re-asserting `has-session`) — one creator resolving one socket dir, which is why the remote-side picker never creates it; mutually exclusive with `OG_REMOTE_RESTORE`. An empty active-window lookup is fatal rather than a blank mirror. |
| `og-remote-loading` | the mirror session's initial window command, set by `og-remote-open` | Spinner, host, session and a caption, so a client switched to a mirror session lands on a loading screen rather than a stray local shell for the length of the daemon's dial and first-window setup. Reads its caption from `${sock}.phase`: the launcher writes the line covering the stretch before the daemon exists, the daemon writes the rest, its teardown removes the file. Ended by the `respawn-pane -k` that turns that pane into the first window's renderer, so it must never exit on its own — before `stampMirrorWindow` the window still carries `remain-on-exit off`, and a pane that exits takes the single-window mirror session with it. A build with no loading binary resolvable falls back to the plain shell. |
| `og-remote-picker` | `prefix + s` `^o` / CLI | Dual-role wrapper for the remote's own session picker (#356). Local role (`<host>`, the floating pane's command): probe leg → interactive `ssh -t` leg → collect leg → hands the pick to `og-remote-open`. All three legs run with `ControlMaster=auto`, so the probe's connection carries the other two instead of each paying a handshake — `og-remote-auth` builds the same master, but only a host that *fails* key auth ever offers that row. Remote role: `--probe` reports resolved `script`/`emit_dir`/`tmpdir` and mutates nothing; `--serve <token> [label]` prepares a 0700-asserted emit dir and execs `tmux-picker-generate --tui --remote-pick` with `OG_PICKER_EMIT` set, plus `OG_PICKER_HOST` from `label` — the ssh name the local side reached it by, which the remote cannot derive, rendered as the header's host badge. Presence of *this script* on the remote is the capability marker — an older picker binary ignores unknown flags and would launch its TUI into the probe, which over SSH is a hang. |
| `og-remote-auth` | `prefix + s` on an `(auth needed)` row | One interactive ssh handshake for a host, run in the picker's popup via `tea.ExecProcess` so ssh owns a real pty and tmux-og never handles the secret. Creates a self-reaping `ControlMaster` (`-M -f -o ControlPersist=@remote_auth_persist`) — `ControlMaster no` still *reuses* an existing master, so this alone makes the probe and the launcher's ssh calls free. It does **not** reach the daemon or the graphics fetcher: `picker/remotebridge/cmd/daemon/main.go` passes its own `-o ControlPath` on the command line, which overrides the config and builds a master of its own, so those two keep authenticating independently — declining the `ssh-copy-id` offer leaves the daemon unable to authenticate (no tty) and it dies into `${sock}.log`, which the script warns about before exiting. Also warns rather than claiming persistence when the ssh config has no `ControlPath` set (OpenSSH's own default), since `-M` then creates nothing for anything to reuse. Offers `ssh-copy-id` with the key from `ssh -G`, walking its identityfile list for the first `.pub` that actually exists (never a hardcoded default — a work key must not land on a personal host). |
