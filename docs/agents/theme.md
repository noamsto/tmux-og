# Theme (light/dark)

The `tmux-client-theme` and `og-remote-theme` rows in `scripts.md` carry the script-level detail.

- **Theme support**: tmux state (`@catppuccin_flavor`/`@thm_*`) and Catppuccin Latte/Mocha colors accordingly, driven by two independent signals now. An external `theme-toggle` run is the only writer of `$XDG_STATE_HOME/theme-state.json`, and also drives tmux via its own `update_tmux`. A terminal theme report (tmux's `client-*-theme` hooks → `tmux-client-theme`, #663) converges tmux state alone — `@catppuccin_flavor`/`@thm_*` — and **never** touches `theme-state.json`; that file is `theme-toggle`'s alone, and once a server is up it is read only as a **cold-start seed** for `@catppuccin_flavor` when the option is still empty at config load (see `generator/render/base.go`'s `pluginConfigs`), never again afterward. **Renderer consistency**: because a terminal report can now diverge tmux state from the file, every in-repo reader prefers the LIVE tmux flavor when running under tmux, falling back to the state file only outside tmux or before `@catppuccin_flavor` is set — `lib-claude.sh`'s `setup_claude_colors` (optional pre-expanded-flavor argument, else one `show-options` fork when `$TMUX` is set, else the file), and the Go `themestate.Detect()` call sites (`picker/statusline`'s `--flavor` CLI flag, `picker/tui.go`/`picker/whichkey.go`'s `readTmuxOpts()`-derived `@catppuccin_flavor`, `picker/splash`'s own `show-options` fork) — none of them modify the external `themestate` module itself, they adapt only at the call site. The flavor is server-global, so with several attached clients the last one to attach or change theme holds. Control-mode clients (the remote bridge) have no tty and never fire the hooks, so a bridge attach cannot flip the theme; a terminal that never answers DSR 996 never fires either (kitty is one such terminal today — it doesn't yet report DSR 997, so these hooks stay dormant there until it does or another terminal is used). An ssh-attached client's report is ignored while any other attached client is local (non-ssh, non-control); an all-ssh/headless server's reports are followed — see the `tmux-client-theme` row in `scripts.md`. A terminal pinned opposite the desktop would revert the desktop on every attach — `set -g @og_follow_client_theme off` disables the handler at runtime. Design: `docs/superpowers/specs/2026-09-16-client-theme-hooks-design.md`.
