# Agent State Files (`/tmp/claude-status`)

File formats, writers, and the derived states (interrupt, dead-agent, staleness) layered on them.

- **Claude status state files** at `/tmp/claude-status/panes/<pane_id>` use simple `key=value` format (state, timestamp, session, optional server — the writing tmux server's `#{pid}`, the prune's ownership key — optional unseen, optional transcript). The `transcript` path is the hook's `transcript_path` (forwarded by the CC plugin's `status.sh`); it powers interrupt detection.
- **Screen-scraped state files** at `/tmp/claude-status/screen/<pane_id>` are written by `agent-detect` (`picker/agentdetect/`) for non-Claude agents, via `statefile.Writer`. `pipe-pane` keeps feeding a pane's output to the same watcher process for the pane's whole life, independent of what's currently running in it, so once an agent exits back to a shell the watcher keeps sampling and manifest matching keeps returning `""` (no rule matches shell output). `Writer.Update` treats that empty verdict as "agent gone", not "nothing to report": it delegates to `Writer.Clear`, which unlinks the file and resets its last-written state so a later real state always writes rather than silently no-opping against stale bookkeeping. Idempotent — clearing twice, or a file already gone, is not an error. `Writer.WithServer` stamps `server=<tmux pid>` after the timestamp line so `claude_prune_stale_state` can tell a live foreign server's state from a dead one's (#709). Every `Update`/`Clear` also mirrors into the pane option `@agent_screen` (best effort, like `bridge_stamp`) — the only way this state reaches a remote-bridge host; see "Remote Agent Status" in `bridge-shipped-state.md` (#635).
- **Background-shell badge** (`bg=N` in a screen state file): a *flag*, not a state. `manifest.Match` returns `(state, flags, bool)`, where flags come from `[[flags]]` rules whose regex holds one capture group carrying a count — evaluated independently of the winning rule, since a background shell outlives the turn that started it and the pane may be idle, processing, or waiting while holding one. `Writer.Update` therefore dedupes on state **and** flags: a shell finishing moves no state, and deduping on the state alone would pin the first count forever. Consumers read the count off the *screen* file whichever source wins the state (`read_pane_state`'s `REPLY_BG`, `collectAgentPanesFrom`'s `bg`) — a hook-fresh pane can still hold shells, and only the scraper sees them. Deliberately absent from `claude_priority_state`/`agentPriority`, and never faded (an old background shell is more interesting, not less) — same additive shape as `@pr_draft` on a PR badge. Only `claude.toml` populates it: Cursor's `N task` counts *foreground* tool calls, which `processing` already implies, and Codex awaits a capture. It is not in the per-window icon column, which is sized exactly at `MAX_ICONS * 3 + 2`; it renders in the status-line aggregate and the picker rows.
- **Interrupt detection**: no Claude Code hook fires on an Esc-interrupt, so an abandoned turn would otherwise sit at `processing` forever. `read_pane_state` reclassifies a `processing` pane to `interrupted` (a derived state, never written to disk) once it has been quiet past `CLAUDE_INTERRUPT_CHECK_AGE` **and** the transcript tail holds `[Request interrupted by user…]`. The next prompt's `processing --force` write clears it. The tail verdict is cached at `/tmp/claude-status/interrupt/<pane_id>` and reused while the stamp is newer than the transcript (`[[ -nt ]]`), so the 1s pollers don't fork `tail` per halted pane per tick.
- **Dead-agent detection** (`claudeStatus.assumeDeadAfter`, default 0 = off): the event-driven path clears an exited agent's state from the shell's own prompt mark, and the floor survives as the backstop for shells that emit no OSC 133. **Event (#646):** the `pane-shell-prompt` hook (OSC `133;A`, which fish 4.x emits by default on every prompt redraw — including after a foreground agent is killed) runs `tmux-shell-prompt` → `claude_clear_agent_state`, which removes `panes/<id>`/`screen/<id>`/`interrupt/<id>` and empties the `@claude_status`/`@agent_screen` pane options. Because the files are deleted (not a derived "withdrawn" verdict), the Go consumers (`picker/statusline`, the pickers) that read `panes/` directly stop rendering it too — closing the consumer asymmetry the floor had. The discriminator is `pane_current_command` (the foreground process-group leader's argv[0]) at prompt time: a nested prompt inside a still-running agent reports the agent and is skipped; unknown/empty fails closed. A `@bridge_win` mirror window is skipped whole **before** the clear (#741): its panes run the bridge renderer and their pane state is daemon-shipped, so a renderer re-emitting the remote shell's OSC 133 must not delete `panes`/`screen`/`interrupt` or blank the `@claude_status`/`@agent_screen` options. The ownership guard matches the file's `session=` against the firing pane's `#{session_name}` (a `rename-session` between write and exit, or a session group, fails closed to the backstop). **Floor (backstop):** `tmux-update-icons`' sweep stamps `/tmp/claude-status/live/<pane_id>` (one line, epoch seconds) for every pane whose foreground command is an agent, then `live/.sweep` once the pass completes — strictly last, so a fresh `.sweep` *implies* every agent pane of that pass was stamped, which is what removes any need for a grace window after a resume. `read_pane_state` then withdraws (returns 1 — derived, like `interrupted`; nothing on disk changes) a `processing`/`compacting`/`done` state that is past its own `CLAUDE_STALE_*` threshold on a pane whose stamp has stopped advancing. Positive evidence only: a *missing* stamp never withdraws, a stale `.sweep` deactivates the whole mechanism, `waiting`/`error`/`denied` are never touched, and thresholds below 15s are clamped up to it. `.sweep` is a dotfile so `claude_prune_stale_state`'s glob skips it deliberately. The floor's veto lives in `read_pane_state`, so only its shell consumers honour it (`tmux-update-icons` icons, `claude-status`, `tmux-kill-pane-guard`) — which is exactly why the event deletes the files instead. Precedence: the event clears immediately (and a later sweep has nothing to withdraw); where it never fires (no OSC 133 shell, an old remote's config) the floor's withdrawal applies exactly as before.
- **Window naming/crew reset on last-agent-exit** (#671): `@window_has_agent` (`"1"`/unset, tmux-og-owned, no shadow-compare needed) is the single fact every display consumer gates on — set the moment any pane in a window runs a manifest agent command (`normalize_wrapped_cmd` against `$AGENT_COMMANDS`, the same manifest test `arm_agent_detect` and `tmux-shell-prompt.sh` both already use), unset the moment none do. **Event:** `pane-shell-prompt` passes the firing pane's window id and the window's *current* `@window_has_agent` as two extra hook args (no fork to fetch it); `tmux-shell-prompt.sh` returns immediately unless that value was `1`, then lists the window's panes and, only if none still run an agent, runs the reset's *option* half (`claude_clear_window_display`), stamps `@window_naming_dirty 1`, and forces a reflow. It does not delete: this hook fires with or without an attached client, so its shared-dir `rm`s are owed to the client-gated per-tick pass (#692), the same split the sweep uses. **Backstop:** `tmux-update-icons`' per-window loop (see its row in `scripts.md`) recomputes `has_agent` from the same batched read every tick and runs the identical call on a transition or on the sweep's `@window_naming_dirty` mark — the ground truth for a window with no attached client or a shell with no OSC 133 support. **Client-independent sweep (#692):** the `@og-sweep-tick` caller (`arm_agent_detect force`) computes the same occupancy from its own `list-panes -a` rows and, for a window with no live agent that still carries naming state — explicitly including one whose `@window_has_agent` was never stamped, which no option transition can ever reach — clears `@window_has_agent`/`@window_ai_name`/`@window_task` and forces a reflow. That is what reaches a host whose only clients are control-mode remote-bridge transports (#603/#596), where the `status-format[0]` poller never ticks: the sweep's writes are per-server, so it performs the option half only and marks `@window_naming_dirty` for the shared-dir file deletion, which stays on the client-gated per-tick path (`/tmp/claude-status` is machine-global) — as does the event hook's. `claude_clear_window_naming` is now that one deletion path: it always clears `@window_has_agent` and `issues/<pane>` for every pane (issues die with the window's last agent regardless of naming mode); it additionally clears `@window_ai_name`/`@window_task` and their self-report files only when `@window_manual_name` is unset — a second, durable, tmux-og-owned marker stamped only by the user's own `prefix + ,` rename gesture, which also makes the pre-existing automatic-rename reassert (same `scripts.md` row) leave a manually-renamed window's `automatic-rename off` alone instead of reverting it within ~1s (a real, if narrow, pre-existing gap this feature had to close for "user-renamed window keeps its name" to be provable at all). Nothing ever clears `@window_manual_name` automatically — intended, since the reassert genuinely can't distinguish a user rename from tmux-remux's restore-induced `automatic-rename off` — the user's own escape hatch is `setw -u @window_manual_name`, which reverts the window to automatic naming. Every display consumer is gated the same way: the reflow grid blanks `crew` before computing `@window_crew_disp` when `@window_has_agent != 1`, status-format[1]'s single-line badge wraps the existing bridge-aware crew-name ternary in `#{&&:...}` against it, and both `picker/main.go` and `picker/statusline` blank `crewName`/`crewColor` the same way. `@crew_name`/`@crew_color` (dispatch-owned) and dispatch's own per-pane `@crew_role`/`@crew_state`/`@crew_role_color` are never written by any of this — display-gating only. `@bridge_win` windows are excluded outright at every site (daemon-owned, two-writer race). Known, documented, **not implemented** gap: a dispatcher-lead/role-grid window's `pane-border-format`/`pane-border-status` is set by the external `dispatch`/`crew` harness itself as a window/pane-scope override with `@crew_name`/`@crew_role`/`@crew_state` baked in statically — tmux-og's own `pane-border-format` fallback never reaches a window dispatch has overridden, and there is no tmux-og-owned seam to gate it without writing to a dispatcher-owned option; the follow-up is dispatch's own format consulting `@window_has_agent` itself.
- **Issue self-report files** at `/tmp/claude-status/issues/<pane_id>`: one line, comma-separated ids matching `[A-Za-z0-9_-]+`. Never written by the state machine — only by `claude-status-update issue`. Also cleared, for every pane in a window, once that window's last live agent exits (#671) — unconditionally, regardless of `@window_manual_name`, since a manual window rename has no bearing on whether an issue self-report is still meaningful. The `rm` runs on the client-gated per-tick pass, which the OSC-133 event hook and the #692 sweep both owe it to via `@window_naming_dirty`.
- **Task self-report files** at `/tmp/claude-status/tasks/<pane_id>`: one sanitized line (printables, whitespace squeezed, ≤60 chars) — "what Claude is doing", captured from the latest prompt. Written only by `claude-status-update task`. `tmux-update-icons` mirrors the active pane's task to the window option `@window_task`. Both the file and `@window_task` are cleared when the window's last live agent exits and the window has never been manually renamed (`@window_manual_name` unset, #671) — the option half by the event hook or the sweep, the file `rm` owed via `@window_naming_dirty` to the client-gated per-tick pass — a manually-renamed window keeps its task display, since nothing renders it as part of the window's actual name. The per-tick read of the file is gated on live agent occupancy (#692), so a lingering file cannot re-stamp `@window_task` after the client-independent sweep cleared it.
- **Name self-report files** at `/tmp/claude-status/names/<pane_id>`: one sanitized line (no `|`, ≤40 chars) — a descriptive window title for fallback windows that are unnamed (gated by the `@ai_naming` global). The `UserPromptSubmit` hook seeds it from the first prompt (an instant readable floor) and nudges the pane's Claude to replace the seed with a concise title via `claude-status-update name set`; because the seed populates `@window_ai_name`, the nudge self-suppresses after the first prompt. `tmux-update-icons` mirrors it to `@window_ai_name`. `build_window_label` priority is issue → non-default branch → `@window_ai_name` → `@window_task` → repo basename, so enriched windows ignore the AI name and multiple Claudes in one checkout stay distinct. Both the file and `@window_ai_name` are cleared on the same last-agent-exit/not-manually-renamed condition as the task self-report above (#671; the option half by the event hook or the sweep, the file `rm` owed via `@window_naming_dirty`); its per-tick read is gated on live agent occupancy (#692, same as the task self-report).
- **Watcher registry files** at `/tmp/claude-status/watchers/<pane_id>`: the PID of the `agent-detect` process currently watching that pane on line 1, plus `server=<tmux pid>` on line 2 (the prune's ownership key; line 1 alone for a watcher that could not resolve it), written by `registerWatcher` (`picker/agentdetect/main.go`) at every watcher startup, including re-arms. `ownerMatches` reads line 1 only. A re-arm's registration supersedes the prior watcher's; the superseded watcher notices the mismatch on its own debounce ticker and exits, but never deletes the file itself — deleting would remove the *new* watcher's registration and cause it to spuriously self-evict on its own next ownership check. Removed primarily by the `pane-exited`/`pane-died` hook (`claude_reap_pane`); the `tmux-update-icons` sweep (`claude_reap_dead_panes`, see its row in `scripts.md`) is the ~60s backstop once a pane's id drops out of `list-panes -a`, and tmux server restart still sweeps via `claude_prune_stale_state` for any entry a live pane's supersession left behind (that exit path never deletes its own registration — see above).
- **Staleness**: not a state transition — `read_pane_state` only eases a state's color toward dim grey once its age passes the per-state `CLAUDE_STALE_*` threshold (e.g. `processing` at 300s), over `CLAUDE_FADE_DURATION`. The one age-driven *reclassification* is interrupt detection (above).
- **Self-reported issue ids** show on status line 0 (cap 3 + `+N`) and picker rows (cap 2 + `+N`); they survive `/clear`/compaction and die with the pane or CC session.
