# Multi-host projects (`og project`)

A project is one git repository, identified by its normalized `origin` URL, possibly checked out on several hosts (#1180). Design: `docs/superpowers/specs/2026-11-18-multi-host-projects-design.md`; phases: `docs/superpowers/plans/2026-11-18-multi-host-projects.md`. The code is `picker/project` (package `project`, binary `og-project-bin`), `scripts/og-project.sh` (the shim), `programs.tmux-og.projects` (the option).

**Scope shipped (P1a): read-only.** The only subcommand is `og project status [<project>]`. `open`, `attach`, `detach`, `new`, the snapshot cache (`$XDG_CACHE_HOME/tmux-og/projects/`), the `@og-project-tick` monitor hook and the pickers arrive in later phases; the cache and tick are specified in spec 5.1, not built. `--remote-open <path>` is parsed and stored by `cmd/project` for P1b's `open` and unused today.

**No config means no behaviour change.** No tmux hook, no `-B` tick, no `#()`, no cache file, no probe and no `tailscale` exec happens until a user runs `og project`. Keep it so: any later phase that adds a background driver must be a no-op when there is no `programs.tmux-og.projects` entry and no `@og_project` session (spec 5.1).

## Identity (`identity.go`)

- **The key is `<forge-host>/<owner>/<repo>`**, made by `NormalizeKey`; `ok=false` means "no project key" and the repo is never routed. Scheme, userinfo, port, trailing `/` and `.git` are stripped; only the host is lower-cased (owner and repo keep case, not every forge folds it).
- **Accepted inputs:** `scheme://authority/path` for `ssh`, `git`, `http`, `https`, `git+ssh`, `ssh+git` (anything else, e.g. `file`, is `false`); scp form `[user@]host:path` when the first `:` precedes the first `/`; key form `host/path` when the host holds a `.` or the path has at least two segments (so a dotless ssh-alias key like `gh-work/Org/Repo` normalizes to itself, a one-segment relative origin like `foo/bar` is not a key, and a registry may spell a key directly). Absolute local paths, `../x` and `""` are `false`.
- **The key is validated where it is made, because a remote host controls its own `git remote get-url origin`.** Raw input passes `[A-Za-z0-9._/@+:%~-]` and 512 bytes; a host may hold `_` (`git@gh_work:Org/Repo.git` becomes `gh_work/Org/Repo`); the final key must pass `[A-Za-z0-9._/@+:-]` (so `%` and `~`, which URLs may carry, are rejected there). Whitespace, control bytes, ESC, quotes, `#`, `(`, `)`, `$`, backtick, `\`, `|` and `;` never reach a key. This is what lets later phases write the key into `@og_project`/`@og_project_leaf`, a cache file name or a message unquoted.
- **`git remote get-url` already applies `url.<base>.insteadOf`**, but not ssh `Host` aliases: origin `git@gh-work:Org/Repo.git` yields the key `gh-work/Org/Repo` on that host, which is a different project until the declarative `remotes` list folds it in (P0 finding 5).
- **`LeafName(key)`** is `og-<mirrorname.Part(repo)>-<sha256(key)[:8]>`, derived from the key alone so every controller agrees on the remote leaf session name whatever its local slug collisions are.
- **`Slug(key, taken)`** names only the local hub session: `Part(repo)`, then `Part(owner-repo)`, then `Part(owner-repo-<sha256(key)[:4]>)`, the last returned even if taken. Output is `[A-Za-z0-9_-]` because stock session menus parse session names as commands (`mirrorname`). The raw key belongs in a session option, never in the name.
- **`SafePath`** (absolute, 2 to 1024 bytes, `[A-Za-z0-9._/@+:-]`, no `..` segment) and **`SafeBranch`** (`git check-ref-format --branch` narrowed to `[A-Za-z0-9._/-]`, not `HEAD`, 1 to 255 bytes) gate every value that later rides in a remote shell word. Both charsets contain no quote, so a value that passes needs no escaping inside the single-quoted probe command.

## Registry (`registry.go`)

- **Optional.** Discovery works with no registry; the declarative layer only adds a name, alias folding and a pinned path per host (the one thing discovery cannot find: a host where the project was never opened).
- **Rendered by Nix, read by Go.** `projectsConfig` in `config/tmux.conf.nix` is a `writeText` JSON: `{projects: {<name>: {remote, remotes, hosts: {<host>: {path}}}}, bridgeHosts: [...], tailscale: <bool>}`. `bridgeHosts` is `programs.tmux-og.remote.hosts` split on whitespace; `LoadConfig` reads the file named by `TMUX_OG_PROJECTS` (`project.Env`), unset or empty means a zero `Config`. `LoadConfigFile` uses `DisallowUnknownFields`, so a field added to the Nix JSON without the Go struct fails loudly. A sibling reader rather than an `ogconfig` field, so the picker and splash binaries do not depend on this shape (P0 finding 6).
- **The `og-project` shim exports `TMUX_OG_PROJECTS`** only when `@projects_config@` was substituted; unsubstituted (bats) it leaves whatever the caller set. `float-conf-assertions` fails the build if any of its placeholders survives substitution, since the bats suite runs the shim unsubstituted and would not notice. The bats suite requires `OG_PROJECT_BIN`.
- **Module option** `programs.tmux-og.projects` is `submodule { freeformType = attrsOf projectType; options.tailscale.enable }`, `projectType = {remote = str; remotes = listOf str = []; hosts = attrsOf {path = str} = {}}`. The option name `tailscale` is therefore taken: **a project cannot be named `tailscale`**, because the freeform attribute and the declared option collide. `modules/home-manager.nix` passes `projects = removeAttrs cfg.projects ["tailscale"]` and `projectsTailscale = cfg.projects.tailscale.enable` to `tmux.conf.nix`. `LocalHost` (`"local"`) names this machine in `hosts.<host>`.
- **Hosts probed** are `LocalHost`, then `Config.RemoteHosts()`: `bridgeHosts` first, then declared hosts (projects sorted by name, hosts sorted), deduped. A declared host that is not a bridge host is still probed; a host is an ssh alias, nothing more.
- **`Merge(c, probes)`**: a declared project's canonical key is `NormalizeKey(remote)`; each `remotes` entry is normalized into an alias map. An invalid `remote`, alias or `SafePath`-failing declared path is an error and is skipped, never fatal. A declared `remote` or alias that may carry credentials is rejected the same way; the error names only the project and never echoes the value. **One rule, in Go and Nix**: `credentialBearing` (`registry.go`) and `modules/project-credentials.nix` (`urlHasCredentials` in `modules/home-manager.nix`, an evaluation-time `assertions` entry, because the registry JSON is a world-readable `/nix/store` file) refuse any `?` or `#`, and allow userinfo only as a bare `[A-Za-z0-9._-]+` username, either on an `ssh`, `git`, `git+ssh` or `ssh+git` scheme (`ssh://git@host/..`) or in scp form (`git@host:..`); a password, any http(s) or other-scheme userinfo is refused. The flake check `project-credential-assertions` runs the Nix function over `picker/project/testdata/credential-cases.json`, the same table `TestCredentialBearingCases` runs Go over, so the twins cannot drift. A probe contributes only when its `Err` is nil; the first snapshot per (project, host) wins, **except** that a declared (project, host, path) claims the snapshot of that host whose `RepoPath` or any worktree path equals the path, whatever its key (the declarative path wins, and `RepoPath` becomes that path). **A declared host matches the probe of that host or any probe it was folded into** (`HostProbe.Aliases`, see self detection below); the matched snapshot lives under the probe's `Host`. A declared host whose probe answered but matched nothing gets a snapshot with `ErrNoCheckout` under the probe's `Host`, its text still naming the declared host (`no checkout of <key> on <declared host> at <path>`); one whose probe failed gets the probe's error. Misses are recorded after every match of a probe, so a project declared on two aliases of one machine keeps the alias that matched; when both miss, the first alias in name order names the error. A host absent from `probes` contributes nothing. Projects sort by key, hosts by probe order.
- **`Matches(query)`** accepts the key, the declared name, an alias, or `NormalizeKey(query)` equal to the key or an alias, so `og project status https://github.com/o/r.git` works.
- **`Duplicates`**: a non-empty branch checked out on two or more distinct hosts (hosts whose snapshot has no `Err`), `HeadsDiffer` when the head shas differ. The count is per distinct host, so a branch on one host is never a duplicate.

## The probe (`probe.go`, `runner.go`)

**Two calls, deliberately separate.** The snapshot probe (`ProbeScript`, `probekit.SnapshotProbeTimeout` 8 s) is local-only: git reads, no network. The heads call (`HeadsScript`, `probekit.HeadsProbeTimeout` 6 s) runs `git ls-remote` against the forge. They are split so a slow or down forge can only make a drift note say `remote head unchecked`, never time out the snapshot and lose the host; and so a tick can skip the network. The heads call runs only for projects a command displays (`status`: at most 32 per host, `Err == nil` and a `DefaultBranch`), and its parser takes whatever arrived even after an error, because each `ls-remote` is independently bounded by `timeout 4` where the host has `timeout(1)`. The heads script does not pipe through `head`: stdio buffering would lose answers already printed when a deadline kill lands. Go bounds the request instead, to at most 32 validated (path, branch) pairs. It runs git with `GIT_TERMINAL_PROMPT=0 GIT_ASKPASS=true SSH_ASKPASS=true SSH_ASKPASS_REQUIRE=never GCM_INTERACTIVE=never`, so a read-only status can never open a credential, askpass or host-key prompt. `SSH_ASKPASS=true` is there because OpenSSH older than 8.4 ignores `SSH_ASKPASS_REQUIRE`.

**Run as `sh -c '<script>' _ <paths...>`**: locally via `ProbeArgv` (`sh`, never ssh) for `LocalHost`, else `ssh -o BatchMode=yes -o ConnectTimeout=2 -T <host> -- <ProbeRemoteCommand>` (`probekit.SSHArgv`). `$@` are the registry paths for that host; only `SafePath` ones are passed, others are dropped. A host alias that is empty, starts with `-` (it would be an ssh option) or holds a byte outside `[A-Za-z0-9._@:+-]` is refused with `ErrInvalidHost` before any exec. The `Runner` interface is the seam tests fake; `ExecRunner` runs each call in its own session (`Setsid`) and SIGKILLs the process group on cancel, with `WaitDelay` 500 ms, so a `ProxyCommand` child cannot outlive the deadline holding the pipes (the `sshKillCtx` pattern). Stdout is capped at `MaxOutput` (1 MiB), stderr at 64 KiB; a truncated stdout drops its partial last line, since a row cut mid-field could still parse.

**Failure classification** is `probekit.ClassifyProbeErr` (own deadline, `errors.Is(ctx.Err(), DeadlineExceeded)`). Stdout is parsed even on error: `ClassifyProbeErr` needs it for the Tailscale check URL, and `FetchHeads` keeps the heads that answered. A failed snapshot probe is still not a partial answer: `Merge` ignores it, so a host that times out shows only its error row, and self detection needs `Err == nil`. A non-255 ssh exit renders `probe failed — remote command exited <code>`. A needs-Tailscale-check host (`check` mode ignores `ConnectTimeout`, #486) is bounded by the deadline like any other.

**Script rules (the quoting and degrade rules are pinned by tests; the POSIX-sh comparison of `sh` against `dash` runs wherever `dash` is on PATH, which `picker-go-tests` provides; the output caps below are not test-pinned):**

- **No `'` and no `\` anywhere.** The script rides inside single quotes through the remote login shell, often fish, where `\` and `\'` are escapes (the `remoteZoxideScript` rule). Double quotes are fine. Consequence: the scripts cannot write `\n`; newlines come from `nl=$(echo; echo x); nl=${nl%x}` (a command substitution strips only trailing newlines, so the `x` guards it) and rows are `printf "...$nl"`.
- **POSIX `sh` (dash) only**: no arrays, `local`, `[[`, `$'..'`; `printf`, never `echo`, for data.
- **Degrades silently, exit 0**: no tmux server, tmux, zoxide, git or `timeout` means fewer rows, never an error (an error would mark a reachable host unreachable). The I row comes first, then `command -v git || exit 0`.
- **The tmux call is `probekit.RemoteTmuxCmd(...)`**: its two `TMUX_TMPDIR` legs (`/run/user/<uid>`, then `/tmp`) and per-user nix profile fallback are shared with the picker (`og-remote-open` resolves the same tmux binary fallback in `picker/remoteopen/probe.go`, but picks one tmpdir by `uname -s`, `/tmp` on Darwin and `/run/user/<uid>` elsewhere, with `OG_REMOTE_TMPDIR` overriding and no fall-through to the other), and it is fish-safe (no `var=value` assignment on the command line). `ProbeScript` is a `var` because it calls it; `HeadsScript` is a `const`.
- **Every path is charset-checked before it is examined or echoed** (`safe()`); Go re-validates every row, so the script check is defence in depth.
- **A credentialed origin never crosses the wire**: userinfo is stripped from a `scheme://` origin remote-side (`https://user:tok@host.example/..` becomes `https://host.example/..`) before the R row is printed. An scp-form `git@host:path` keeps its user (it is not a secret); `NormalizeKey` drops it.
- **Default branch** comes from `symbolic-ref --short refs/remotes/origin/HEAD`, `origin/` stripped, fallback `main`; the forge controls the value, so it is only ever expanded as `"$d"` inside the script and re-checked by `SafeBranch` in Go (`""` when it fails).
- **Common dir** is resolved with `cd -P "$c"` + `git rev-parse --git-common-dir` + `cd -P` + `pwd -P`, not `--path-format=absolute`, so the probe works on git older than 2.31. Both `cd`s are `-P` because git prints the common dir relative to the physical cwd, so a symlinked candidate must be entered physically or the relative dir resolves against the wrong parent. `unset CDPATH` keeps `cd` silent (a `CDPATH` hit prints the directory into the captured output).
- **Identity** (`I` row) is `grep . /etc/machine-id || sysctl -n kern.uuid || uname -n` plus the user. An empty machine-id field means unknown and never matches.

**Output caps (not test-pinned):** whole body through `head -n 5000`; 1000 tmux window lines; candidates deduped, then 150 examined, 60 repos emitted; 2000 worktree lines per repo; the zoxide list `head -n 300`. The heads call has no `head` cap; Go bounds it (see above).

**Candidate roots, in order, deduped before the 150 cap and again by resolved common dir:** (1) registry paths (`$@`); (2) `@git_root` of every tmux window, only when `@bridge_win` is empty and `@git_root` is non-empty; (3) `zoxide query -l` (`command -v zoxide`, else `/etc/profiles/per-user/<user>/bin/zoxide`, the per-user nix profile a non-interactive ssh PATH lacks, P0 finding 2). A candidate that is not a directory, not in a git repo or has no `origin` yields no row (a repo without `origin` has no key).

**Row protocol**, `|`-delimited, one row per line, free-form field last (tmux `-F` formats and `SplitN` rely on it; never tab or newline-delimited, `tmuxformat` enforces it for `picker/**`):

```text
I|<machine-id>|<user>                              first line
R|<common-dir>|<default-branch>|<origin-url>
W|<common-dir>|<head>|<worktree-path>|<branch>     one per `git worktree list --porcelain` record
D|<common-dir>|<ahead>|<behind>|<tracked-sha>
T|<@bridge_win>|<window_id>|<@git_root>|<session_name>
H|<repo-path>|<sha>                                HeadsScript only
```

**`ParseProbe` keeps only well-formed rows; everything a host returns is untrusted.** A line over 4096 bytes, an unknown prefix or a wrong field count counts into `HostProbe.Skipped` (shown as `N unsafe rows skipped`). An `R` row with a `SafePath` common dir whose origin is a local path (`/…`, `.…` or `file://…`) is a normal repo with no project: it and its later `W`/`D` rows are dropped silently, not counted. Any other origin `NormalizeKey` rejects counts its `R` row once into `Skipped`; its `W`/`D` rows are dropped uncounted (`dropped` in `probe.go`). Per row: `I` identity is `<machine-id>|<user>` (first row only, printable, at most 256 bytes); `R` needs a `SafePath` common dir and a `NormalizeKey`-valid origin (first R per common dir wins, at most 200 repos); `W` needs a kept repo, an empty or 40/64-hex head, a `SafePath` path and a branch (a branch failing `SafeBranch` keeps the row with an empty branch and counts into `Skipped`; only a bad path or head drops the row; the first W of a repo sets `RepoPath`, even a bare one, whose empty head makes it not a worktree; at most 500 per repo; no W row means `RepoPath` is the common dir minus a trailing `/.git`); `D` is both-empty (`Known=false`) or both-digits, tracked sha empty or hex; `T` needs an `@N` id, a `SafePath` root and a session name, and attaches to the worktree whose path equals it (a window naming no known worktree is dropped silently). **A window with a non-empty `@bridge_win` is a mirror (spec 3.6) and is skipped without counting**, as is a window outside any repo. Every snapshot comes back `Stale`: no `ls-remote` has run.

## Drift (spec 4)

- `Snapshot.Drift` is the host's default branch against `refs/remotes/origin/<default>` **as of that host's last fetch**, a pure local read. Nothing in the design trusts a host's local default branch; this is shown, not hidden.
- **`DriftChip`**: `main ↓n` behind origin, `main ↑n` local commits not on origin, `main ≠` diverged, `main ?` when either ref is missing, empty when up to date (`main ✓` is deliberately not shown) or the default branch is unknown.
- **`DriftNote`** qualifies the chip: `remote head unchecked` while `Stale` (`ls-remote` failed, timed out or did not run); `origin moved since last fetch` when the confirmed `RemoteHead` differs from `Tracked`. `ApplyHeads` matches by `RepoPath` and clears `Stale` only for a snapshot that got an answer.
- An `H` row is matched to snapshots by `RepoPath`; a snapshot with no answer stays `Stale` and keeps `RemoteHead` empty.

## `og project status` (`status.go`, `cmd/project`)

- Flow: probe `LocalHost` plus every remote host concurrently, each under its own deadline; optionally resolve Tailscale; fold every alias of an already-probed machine into that machine's first probe; `Merge`; filter by the query; fetch heads for what will print; render. `Merge` errors go to stderr as `og project: <err>`. A query matching nothing is `og project: no project matches <q>`, exit 1. More than one positional is a usage error, exit 2; `help`, `--help`, `-h`, and `status --help`/`status -h` (before any config load or probe) print usage on stdout, exit 0; the usage text is `project.Usage` (`usage.go`), shared by the binary and the og model, which prints it for `og project --help` because og intercepts a sole `--help`; none or an unknown subcommand prints usage on stderr, exit 2.
- Output: a `Hosts` block (host column padded to the widest printed host), then per project a header (`<key> (<name>)` when declared), one row per host (`<host>  <path>  N worktree(s)  <chip> · <note>`, or `<host>  <error>`), then one `⚠ <branch> is checked out on a and b (heads differ)` per duplicate, then `Suggested hosts from Tailscale (not configured): ...` only when non-empty; `No projects found.` when there are none.
- Host states: reachable; `needs a Tailscale SSH check` (plus the captured URL from `probekit.TailscaleCheckURL`); `host key changed`; `needs authentication — run og remote auth <host>`; `probe failed — remote command exited <code>` for `ErrRemoteNoServer` (`probe failed — <err>` when the error carries no exit status); otherwise `unreachable — <err>`. A probe that failed leaves the host's declared checkouts as per-host error rows, not a dropped project.
- **Every dynamic string goes through `probekit.SanitizeStatusText` before width math and printing**: host, key, name, path, branch, chip, note, error text, suggestion. Widths are rune counts of the sanitized text. The test fixture is hostile on purpose (ESC, `#(`, quotes, newline, `|` in branch, path, remote, session and stderr) and asserts no ESC, no control byte but `\n`, no `#(`, `'`, `"` or `|` in the output. A new printed field needs the same treatment.
- **Self detection by machine id**: probes are compared by `Identity` (`<machine-id>|<user>`, from `/etc/machine-id`, else `sysctl -n kern.uuid`, else `uname -n`) across all of them, local first: a host whose non-empty identity equals an earlier probe's is the same machine (an ssh alias to another configured host, or to this one, e.g. a tailnet name for itself) and is **folded** into that first probe (`fold` in `status.go`), printing `same machine as <first host>, merged`. Folding appends the alias to the first probe's `Aliases` and adds only the snapshots whose `RepoPath` the first probe lacks, rewritten to the first host (one machine has one checkout per path; the heads call then runs against the first host). So the machine's worktrees are counted once and never reported as duplicates, yet a path declared on the alias, which only the alias was asked to probe (`PathsFor`), still matches: `Merge` matches a claim against a probe's host or any of its aliases. Excluding the alias instead would print a project header with no rows; comparing only against local would double-count two aliases of one remote. `fold` clones both slices, since the first probe's are shared with the caller. Only a probe with `Err == nil` takes part; an empty identity (or empty machine-id field) never matches.

## Tailscale (`tailscale.go`, opt-in, P0 finding 8)

- **Off unless `programs.tmux-og.projects.tailscale.enable`; disabled means no `tailscale` process is ever executed** (`TailscalePeers(ctx, false, r)` returns nil with zero `r.Run` calls; a bats case with a marker-writing fake pins it). tmux-og is public and no code path may require Tailscale; the configured `remote.hosts` list is always the source of truth.
- **The call** is `tailscale status --json` under `TailscaleTimeout` (2 s): local daemon only, no network. With `tailscaled` absent it fails after 2.0 s. Any failure, invalid JSON or `BackendState != "Running"` (`NeedsLogin`, `Stopped`) means "no tailscale source": no suggestions line, exit 0, never a user-facing error. Never run it from `#()`/`status-format`.
- **Peer filter**: `OS` in `linux`/`macOS` (drops `iOS`, `android`, `windows`), `ShareeNode` false, `Self` is not a peer. `Name` is the first label of `DNSName` (the MagicDNS name ssh resolves; `HostName` can differ), lower-cased, must be `[a-z0-9-]+` or the peer is dropped.
- **`Online=true` is never "reachable".** A Tailscale-SSH `check`-mode peer is `Online` yet hangs ssh until killed (#486). `Online=false` can only annotate (`(Tailscale reports it offline)`) or, in later phases, skip dialing; the probe and `ClassifyProbeErr` stay authoritative.
- **Matching peers to configured hosts** goes through `ssh -G <alias>` `hostname` (first label, lower-cased), not the alias string, since `remote.hosts` entries are ssh aliases. An alias that fails the `ProbeHost` alias rule is never passed to `ssh -G`. An alias that resolves to no peer is simply not subject to the offline signal; a peer matched by no alias is a suggestion, sorted, never auto-added.

## What a remote needs

`sh` and `git` on the ssh PATH, and an `origin` remote per checkout. Optional, each degrades to fewer rows: `tmux` (windows attach to worktrees), `zoxide` (candidate source 3), `timeout(1)` (bounds each `ls-remote`), a machine id source (`/etc/machine-id`, `kern.uuid` or `uname -n`) for self detection. Nothing from tmux-og is needed remotely. The login shell may be fish; the script rules above keep it working there.

## Known limits

- Two clones of one repo on one host: the first found wins (candidate order above) unless the registry pins a path. A host's second clone is not a second snapshot.
- Discovery sees a repo only through a candidate source; a never-opened, never-visited checkout is invisible until declared with `hosts.<host>.path`.
- `og project status` makes a probe ssh and a heads ssh per host per run, uncached; the P2 cache and tick are what make this cheap in a picker.
- A repo without `origin`, or with a non-remote origin, has no key and is not shown. A local-path origin is dropped silently; any other unkeyable origin counts its `R` row once into `Skipped`, its `W`/`D` rows uncounted.
- Aliasing across ssh `Host` aliases (`gh-work` against `github.com`) needs `remotes`; it is not inferred.
- A declared path reached through a symlink never matches: `matchPath` compares the declared logical path with the physical paths git reports, so the host shows `no checkout of <key> on <host> at <path>`. Declare the physical path.
