## Step 3 — `#{I/f:...}` client interrogation replaces manual `client_termfeatures` token matching; `#{I/e:...}` replaces the session-environment SSH_CONNECTION read

**Why now works:** tmux 3.8's `I` format modifier (`format.c:6127-6140`, `format.c:6288-6314`) does a **live per-client lookup** rather than string matching a cached feature list: `I/f:<name>` returns `"1"`/`"0"` from `tty_feature_present()` for the format's *client* (`ft->c`), and `I/e:<name>` returns the *client's own* environment entry (`ft->c->environ`) rather than the session's copied environment table — confirmed in `format.c`: both require `ft->c != NULL` and a client not in `CLIENT_UNATTACHEDFLAGS` (dead/suspended/exiting), which every row of a `list-clients -F` listing and every `-c <client>` target of `display-message` satisfies. `display-message` supports `-c target-client` (`cmd-display-message.c:42`), so `tmux-splash-maybe.sh` can interrogate the *attaching* client directly instead of reading the session's environment table.
