# Stabilise the macOS-flaky bridge / float integration tests (#1255)

Goal: make five bats cases deterministic on a slow 3-core runner without weakening what they prove. Test-only change unless step 6 proves a product fault.

## Evidence so far (CI logs, darwin `macos-15`)

| Test | CI failure | What it races |
| --- | --- | --- |
| `float-drag-integration` 21 "a local client resize follows a remote float the remote refits itself" (PR #1249 run 45374617826) | `remote window never reached 45x12` from `resize_client` (5s budget, no daemon log printed) | resize propagation (local client → 1s nudge poll → `refresh-client -C` → remote window) gets a fixed 5s; with the remote `window-resized` refit hook also running, the later `settle_agree` one-shot 0.5s hold is a second fixed window |
| `remote-m2-integration` 4 "daemon repaints mirrored content after a remote geometry change" (#1247 attempt 2, 2092ms) | line 649 `[ "$dst_screen" = "$src_screen" ]` failed, dims already agreed | the 50×0.1s loop exits the moment *dimensions* agree; screens are captured immediately, before the reseed that follows the geometry reconcile has painted |
| `remote-m2-integration` 5 "a non-current mirrored window converges after a client detaches (#979)" (#1247 attempts 1 and 3, 20.8s and 21.8s; passed in 3.2s on attempt 2) | `wait_src_all '150x*'` timed out after the existing 20s `RESIZE_CONVERGE_BUDGET_SECS` | already a condition wait with a 20s budget, so this is not "too short". CI `size_failed` output on attempts 1 and 3: `rem:1 150x44`, `rem:2 100x29` (the non-current window never left the departed human's size) and `sz-b.log` shows only the owner claim: a product non-convergence, see Step 6 |
| `float-tool-focus` 1 "a second tool press focuses the open float" (#1247 attempt 3) | line 143 `second press did not focus the open float`; dump `%0|0||1` / `%1|1|yazi|0` | `press()` ends with a fixed `sleep 0.5`; the assertion reads `pane_active` once |
| `client-theme` (PR #1245 run 45369987879 attempt 2: cases 4 and 5) | case 4 `wait_for 20 applied_is light` timed out (report lost); case 5 `thm_bg_is` read once right after `wait_for flavor_is latte` | the reload sets the flavor before it re-derives `@thm_*`, so a single read of `thm_bg` after waiting on the flavor races it; and a theme report sent while the attach client is not yet reading its tty is lost |

Local reproduction on Linux with CPU contention (`taskset -c 0,1,2` + 4 and 16 busy loops: 20 runs; `taskset -c 0` + 8 hogs: 8 runs) did **not** reproduce test 21 (0/18 failures; runs 2-4x slower). Contention that is purely CPU does not trip it, so the failure is darwin-specific or needs fork/IO contention. The plan therefore (a) fixes the demonstrable races in the test code (condition waits on the asserted state), and (b) keeps a Linux loaded loop as the before/after measure, with an honest statement of the rates (baseline may already be 0/N on Linux; the CI failure rate is cited from the run ids above).

## Shared helper decision

`tests/helper.bash` has no wait/retry helper. The suites each carry their own in-file poll helpers (`wait_agree`, `wait_src_all`, `type_until`, client-theme's `wait_for`), and each bats check copies only the files it reads (CLAUDE.md), so a new shared helper would force `flake.nix` edits on four checks plus the remote-m2 shard/coverage derivations. Decision: reuse and extend the existing in-file helpers (all four already follow "poll until true with a budget, print last observed values"); no new shared file. Where a budget is a bare constant (`resize_client` 5s, `wait_agree` 2s, `wait_tiled_agree` 2s) it becomes the file's one budget constant (20s, wall-clock via `SECONDS`) and failure output gains the daemon log tail.

## File list

- `tests/float-drag-integration.bats` — `resize_client` (budget, diagnostics), `settle_agree` (condition wait on refit-landed then agreement, then hold), test 21 hook records the refit it applied.
- `tests/remote-m2-integration.bats` — test 4 waits on screen equality; test 5 per step 6.
- `tests/float-tool-focus.bats` — `press()`/assertions become condition waits.
- `tests/client-theme.bats` — `wait_for` wall-clock + 0.1s granularity, decoy test budget.
- `docs/agents/` — a one-line note in the doc of the area only if a product fix lands (step 6b).
- `docs/superpowers/plans/2026-11-24-stabilise-macos-flaky-bridge-tests.md` — this file.

- [ ] **Step 2: float-drag — condition waits.** Files: `tests/float-drag-integration.bats`.
  - (a) Add `CONVERGE_SECS=20` beside `BUDGET_SECS=12` (which stays: it bounds `mirror_up`). `resize_client`, `wait_agree`, `wait_tiled_agree` and `settle_agree`'s first loop use it, and the 4s clamp loop in the "borderless float near the far edge" test uses it too: every fixed 2-5s window in the file.
  - (b) Every timeout path prints the last observed values, both window sizes (SRC and DST) and the daemon log tail.
  - (c) Test 21's SRC hook becomes `resize-pane -t $RF -x 60% -y 70% ; move-pane -t $RF -X 20% -Y 15% ; set-option -gF @refit_for '#{window_width}x#{window_height}'`. The `-F` is required: a hook command's formats are expanded only for commands that take `-F` (`client-theme.bats` ~line 357 records this for a bare `set -g`). The loop splits `sz` into `w h`, runs `resize_client "$w" "$h"`, then `settle_agree "${w}x$((h - 2))"`.
  - (d) `settle_agree [expected]`: with an argument it first polls (CONVERGE_SECS) until `$SRC show-options -gv @refit_for` equals it (the remote's refit has run for this size), then polls until `geom DST LF == geom SRC RF`, then keeps the 0.5s hold and re-check (it detects a late local writer; a slow runner can only make that pass vacuously, never fail). Tests 20 and 22 call it with no argument and skip the first poll.
  - (e) Root cause first (task item 3): read the context of CI run 45374617826's `remote window never reached 45x12`. The new diagnostics distinguish "refresh-client -C late" from "never sent" on the next failure; if local loaded runs ever show the daemon never converging, step 6's product-fault branch applies.
  - Proof: `bats tests/float-drag-integration.bats` green (22 cases).
- [ ] **Step 3: remote-m2 4 — wait on the asserted state.** Files: `tests/remote-m2-integration.bats` lines ~634-649. - [ ] **Step 4: float-tool-focus 1 — resend until the state holds.** Files: `tests/float-tool-focus.bats`. As shipped: `press()` has no trailing sleep; `press_until <key> <cmd...>` presses, then polls the asserted state (20s) and presses again every 3s. Measured: a press sent straight after the previous float appears never reaches its bind (the bind's own window option stays unset) and any pause of 0.2s or more makes it land, so a longer wait alone cannot fix it (an earlier draft of this step, wait-only, failed deterministically unloaded). A bind that stacked floats leaves the first float inactive, so the wait times out and the case fails. Whether the drop is the harness or the bind is not established (follow-up). Proof: `bats tests/float-tool-focus.bats`.
