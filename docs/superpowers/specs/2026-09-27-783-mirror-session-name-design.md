# Spec — #783: sanitize remote session names before they become local session names

## Problem

`og-remote-open` names the local mirror session `${host}-${sess}` (`scripts/og-remote-open.sh:397`), where `sess` comes from the remote's `list-sessions` (or the picker row, or the daemon's hand-off `exec(remoteOpenBin, host, sess)` — `picker/remotebridge/cmd/daemon/main.go:339`). The only filter on `sess` is `shell_quotable` (no backslash). Two consequences, both measured on the pinned wrapper (`#{version}` = next-3.9):

1. **Local command injection (the issue).** `new-session -s` format-expands its argument (`-s 'a##(x)'` → session `a#(x)`), and tmux's stock `MouseDown3StatusLeft`/`M-MouseDown3StatusLeft` binds (still live in our config — the conf does not rebind them on this base) are `run-shell -C "display-menu … -T '#[align=centre]#{session_name}' … #{S/t:…'Switch To #[underscore]#{session_name}'…}"`. `run-shell -C` expands then **parses** the result as commands, and display-menu expands title/items again. So a remote session named `x' '' ; run-shell 'touch S' ; display-menu -T 'y` (quote break-out) or `x##(touch S)` (→ local `host-x#(touch S)`, command substitution) runs local commands on a right-click of the session pill — on the mirror (title) or any other session (Switch-To loop lists every non-active session).
2. **Broken targeting (latent, same root).** next-3.9 does not rewrite `.`/`:` in session names, but targets split on them: `has-session -t '=a.lan-x'` → `can't find pane: lan-x`; `=h.x:y-…` → `can't find session: h.x`. So a host or remote session name containing `.` or `:` already defeats og-remote-open's dedup loop (`has-session -t "=$local_sess"`) and its final `switch-client -t "=$local_sess"`.

Also: the mirror's initial window is `new-session -n "$sess"` — `-n` is format-expanded too (`-n 'w##(x)'` → window `w#(x)`), and that window name is raw until the daemon's `applyMirrorName` renames it with its sanitized (`##`-escaped) form.

Violated invariant (CLAUDE.md): "Remote-derived values are sanitized daemon-side before any local format renders them". A session name is rendered by stock formats we do not control, so the name itself must be inert.

## Requirements

R1. **Producer-side sanitization.** og-remote-open derives the local mirror session name from the host and remote session name through one function that maps every byte outside `[A-Za-z0-9_-]` to `_`, byte-wise (`local LC_ALL=C`, so the mapping is identical whatever locale the tmux server or picker runs under — measured: in a UTF-8 locale bash maps a multibyte char to one `_`, in C to one `_` per byte). Applied to both halves: `local_sess = part(host) + "-" + part(sess)`. The host half is local config, not hostile, but `.`/`:` in it break targeting (Problem 2), and `@`/`:` appear in legitimate ssh targets (`user@host`, IPv6).
  - The resulting name never needs `##` escaping: no `#`, quote, `;`, space, `{`/`}`, `$`, `.`, `:` survives.
  - Collision suffixes (`-remote`, `-remote-N`) and `sock_name` are built from the already-sanitized name; the separate `sock_name` sanitization becomes redundant and is removed (the socket path uses `local_sess` directly).
R2. **Raw identity preserved.** `@bridge_session` keeps the raw remote name (og-remote-open line 509 and the daemon's `daemon.go:782` re-stamp, unchanged); `OG_BRIDGE_SESSION`, the loading pane's argv, and every ssh/remote command keep using raw `$sess`. Only local tmux *names* change.
R3. **Initial window name.** `new-session -n` gets the sanitized session half (`part(sess)`), not raw `$sess` — same reason as R1 (format-expanded, and window names are not guaranteed a single expansion everywhere). The daemon renames it on first-window reuse as today.
R4. **Identity is the raw pair, never the name.** Before the name walk, og-remote-open looks the mirror up by its raw pair: `list-sessions -F '#{session_id}|#{@bridge_host}|#{@bridge_session}'` (session last, so a `|` in it stays in the last `read` field), matching `@bridge_host == host && @bridge_session == sess`.
  - Found with an allowlisted name (a post-#783 mirror, possibly with a `-remote[-N]` suffix) → reuse that name. This also fixes a latent duplicate: today's walk stops at the first *free* name, so once `h-a_b` is freed a pair living at `h-a_b-remote` would get a second mirror.
  - Found with a non-allowlisted name (a mirror opened before this change, e.g. `h-x#(touch S)`, `user@h-main`) → retire it, with the same ownership proof the existing dedup uses: signal the PID in `<@bridge_sock>.pid` (existing `reap_daemon`) **only** when `$ctl --sock <@bridge_sock> ping _` succeeds or answers the old-protocol `— reopen the bridge` reply; a stale pidfile alone never earns a signal (it may name a recycled unrelated PID). Then `kill-session -t <session_id>` and remove the sock/pid/phase files; fall through to create a sanitized mirror. Targeted by `session_id` because the raw name may not be a valid target (Problem 2). The ctl/daemon path resolution moves above the lookup so retire can use `$ctl`.
  - Several matches (duplicates an older walk or a pre-upgrade open can have left): reuse the first allowlisted match in list order; retire every non-allowlisted match; leave any further allowlisted matches alone (they are sanitized, so harmless, and the old first-free walk is what made them — out of scope to reconcile).
  - Not found → the existing walk from `base_local_sess`: an occupied name whose options match the pair is reused (race cover); a legacy session (`@bridge_host` = host, no `@bridge_session`) is adopted only when sanitization did not alter the name (`base_local_sess == "${host}-${sess}"`), since otherwise the name cannot prove which remote session it mirrors; anything else suffixes `-remote`, `-remote-N`. Distinct remote sessions that sanitize alike (`a.b`/`a_b`, `a b`/`a_b`) therefore never share a local session.
  - `@bridge_session` is stamped **before** `@bridge_host` after `new-session`, so a concurrent walk or picker probe never sees a host-set/session-empty mirror and mistakes it for a legacy one (`parseBridgeMirrors`/`parseBridgeSessions` skip rows with no `@bridge_host`).
R5. **Picker consumers.** `picker/remote.go`:
  - `localBridgeSession(host, sess)` (legacy key: `firstPaintBridges` indexes every open mirror under `legacy\x00<local name>` before the probe, and `bridgeSessionPresent` looks up `legacy\x00localBridgeSession(host, sess)`) applies the same byte-wise mapping, so first paint still hides the rows of already-mirrored remote sessions whose names were altered.
  - `sessionDisplayName(name, bridgeHost)` trims the sanitized host prefix (`part(bridgeHost)+"-"`), so a dotted/`@` host still displays trimmed.
  - Everything else keys on the real local name read back from tmux (`parseBridgeMirrors`, `parseBridgeSessions`, `parseBridgeSessionNames`, kill/detach by `item.target`) or on the raw `@bridge_session` pair key — compatible, no change.
  - `parseBridgeMirrors`' legacy branch (no `@bridge_session`) derives sess by trimming the raw `host+"-"`; with a sanitized host half that no longer matches and the row is skipped. Only pre-`@bridge_session` mirrors take that branch (every mirror since is stamped by both og-remote-open and the daemon), so skipping is acceptable — stated, not changed.
  - The Go mapping lives in one new package, `picker/mirrorname` (`Part(s)`, `Local(host, sess)`), used by the picker and by the daemon's fallback (R6). Go + shell are then a duplicated rule: add it to CLAUDE.md's "Duplicated tables must stay byte-identical" bullet, and test both against the same vector list.
R6. **Other consumers — compatible, no change** (verify in plan): `og-remote-detach` (`display-message -t "$sess:"`, `has-session -t "=$sess"` — sanitized names are always valid targets); the daemon (`cfg.LocalSess` from `OG_DAEMON_LOCAL_SESS`, used as a tmux target and as the `run-shell` argv of `reflowRunShellArgs`, which already keeps it out of format expansion — #368); its `fmt.Sprintf("%s-%s")` fallback when the env var is unset (never on the og-remote-open path; the integration tests pass `--local-sess`) switches to `mirrorname.Local` so no unsanitized copy of the rule remains; `tmux-scratchpad` and the splash hook already quote per-consumer (harmless now); statusline reads `@bridge_host` only.
R7. **Docs.** `docs/agents/scripts.md` og-remote-open row: the naming contract (sanitized local name, raw `@bridge_session`, collision suffix). `docs/agents/bridge-daemon.md` placeholder `#TBD-session-name` is **not** in this base (#782 adds it) — do not edit; PR body notes it must become #783 once #782 lands.

## Acceptance tests

A1. Behavioural, real server, built config (new `tests/mirror-session-name-integration.bats` + flake check, same attached-client harness as `rename-bind-integration.bats`): og-remote-open (the real script, fake `ssh`, stub daemon/ctl/renderer, `tmux` → the inner `-L` server) opens two mirrors, A = the quote break-out name, B = the `##(…)` name, each wired to its own sentinel (`$S_A`, `$S_B`, env vars in the server's global environment, so no path characters ride in the name). Click 1, attached to A, right-click the session pill (col 3, row 1): covers title×quote (A) and loop×subst (B). Click 2, attached to B: title×subst (B) and loop×quote (A). Each click asserts the menu really rendered the names under test — the sanitized title and a `Switch To <sanitized other>` item on screen — and that neither sentinel appears within the async window.
A2. Positive control in the same suite, same two clicks, same sentinels, but the two sessions are created with the raw pre-fix names (`new-session -s "host-$hostile"`) and bridge options: click 1 must create both `$S_A` (title×quote) and `$S_B` (loop×subst); after clearing, click 2 must create both again (title×subst, loop×quote). All four {route}×{location} cases are thereby proven observable, each attributed to its own sentinel.
  Note: each click expands both hostile names into one `run-shell -C` command; if a payload does not parse in the loop's single-quoted item position the whole command is rejected. The loop-position payload may need adapting until A2 is observably red→green; the issue's two names stay the title-position payloads.
A3. Counterfactual (recorded in REVIEW_NOTES/PR Testing, not shipped): A1 run against the base revision's og-remote-open in a scratch copy → sentinel created (red); fixed → green.
A4. Real server, identity: remote `a.b` then `a_b` → two distinct local sessions (`host-a_b`, `host-a_b-remote`), each with its own raw `@bridge_session`; reopening each resolves to its own session; after killing `host-a_b`, reopening `a_b` still resolves to `host-a_b-remote` (pair lookup, not first-free name). A pre-#783 raw-named mirror of a pair (created directly with the raw name and both options) is retired on reopen — the raw session is gone and the pair now lives under the sanitized name; when its pidfile names a live unrelated process (a test `sleep`) and its socket does not answer ping, that process survives the retire.
A5. Fake-tmux unit cases (`remote-cold-start.bats`): hostile `sess` → `new-session -d -s <sanitized> -n <sanitized part>` and `set-option … @bridge_session <raw>`; dotted host → sanitized prefix; the legacy-clause tightening; existing cases green.
A6. Go: `localBridgeSession`/`sessionDisplayName` table tests with the shared vectors (incl. multibyte → one `_` per byte); existing picker tests green.
A7. `nix build .#default`, `nix flake check`, `nix build .#lint` pass.

## Non-goals

- Rebinding or hardening tmux's stock menus (#782's territory).
- A sweep of pre-#783 raw-named mirrors that are never reopened: they keep their raw name (and the exposure) until reopened (R4 retires them), detached, or closed. Likewise a raw-named ghost that tmux-remux restores from a pre-upgrade snapshot. Named as residual in the PR body with the remedy (reopen, `prefix + s` detach, or kill the session).
- Displaying the raw remote name in the picker instead of the sanitized one.
- Atomicity of `new-session` + the two `set-option`s (a concurrent open of a colliding name in that sub-millisecond window) — pre-existing, unchanged; noted as residual.
