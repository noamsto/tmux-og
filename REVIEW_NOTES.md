## Deferred (not blocking, not fixed this round)

- **MEDIUM** — `scripts/tmux-update-icons.sh:239`'s comment claims a `remain-on-exit` corpse pane reports an empty `pane_current_command`; measured false (a dead pane keeps reporting its last live command). Real consequence: an agent that dies inside a `remain-on-exit on` pane (not tmux-og's default for non-mirror windows, but user-config-reachable) reads as permanently occupying its window in both the poller's `win_procs` scan and the event path's `list-panes` scan, so `@window_has_agent` never clears there. Fix: correct the comment; filter dead panes out of the occupancy scan (`#{?pane_dead,,#{pane_current_command}}` or an `-f` filter on the event path's `list-panes`). Narrow blast radius (non-default config), deferred rather than expanding this PR's scope further.
- **MEDIUM** — `scripts/tmux-shell-prompt.sh` forks twice (`display-message` + `list-panes`) on every prompt redraw of any shell pane sharing a window with a still-live agent, since the cheap `@window_has_agent == 1` gate passes for the whole time that sibling agent runs. Could fold the `@bridge_win`/`@window_manual_name` read into the same `list-panes` call already being issued. Efficiency, not correctness; deferred.
- **LOW** — `scripts/lib-claude.sh`'s `claude_clear_window_naming`'s two `tmux set` calls lack the `2>/dev/null || true` its sibling `claude_clear_agent_state` carries; only reachable via a dead tmux server (not a dead window — measured `tmux set -qw -t '@999'` still exits 0), so under `set -euo pipefail` a dead-server race could abort before the `rm -f` loops run, leaving files for the ~60s sweep to catch instead. Narrow.
- **LOW** — CLAUDE.md's #671 bullet says `@window_has_agent` is `"1"/unset`; the code only ever writes `"1"` or `""` (empty string), never truly unsets the option. Cosmetic wording mismatch.

None of the deferred items were assessed by any reviewer as blocking; all are either narrow (require non-default config or a dead server), efficiency-only, or cosmetic. Flagged here for a future pass rather than expanding this PR.
